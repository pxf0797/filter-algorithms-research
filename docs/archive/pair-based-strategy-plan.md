# 基于多空对(Pair)的B周期交易策略（完善版）

> 从"瞬时Sig值"升级到"趋势段(Pair)"——完整处理半边Pair与退出机制

---

## 前言：这一版改了什么

上一版方案（`docs/backtesting/b-cycle-gating-plan.md`）用"瞬时Sig值"来判断B周期是否入场。方向是对的，但它把"此刻的信号"当成了"这一段趋势"，导致三个细节没说透。你提出的4点意见——(1)大方向对细节不对、(2)应以多空对为单元、(3)半边Pair要专门处理、(4)退出机制要补齐——本版逐条回应。

本版做了三个关键升级：

| 升级点 | 上一版 | 本版 |
|--------|--------|------|
| **策略单元** | 瞬时Sig值（此刻是多是空） | 多空对Pair（这一整段趋势是多是空） |
| **半边Pair** | 未处理，等于永远滞后 | 新增识别 + 可靠性评分 + 三种处理模式 |
| **退出机制** | 只有保护期止损 + Sig反转 | 三类退出（趋势偏离 / 进入下一Pair / 上级否定）+ 明确优先级 |

这三点正好对应你的第2、3、4条意见。下面从"为什么"讲起。

## 一、为什么用多空对(Pair)而不是瞬时Sig

### 1.1 Sig与Pair的本质区别

Sig是每一根K线上的一个瞬时值（+1做多、-1做空、0观望）。Pair是把连续同向的Sig合并成的"一整段趋势"，有起点、有终点、有方向。二者的差别不是精度问题，而是"看问题的尺度"问题：

| 维度 | 瞬时Sig值 | 多空对Pair |
|------|-----------|------------|
| 回答的问题 | "此刻是什么状态" | "这一段趋势是什么" |
| 稳定性 | 每根K线都可能翻动 | 左端（起点）一旦锁定永不变 |
| 抗噪能力 | 单根噪声就误导 | 跨零合并吸收单根抖动 |
| 交易对应 | 一个信号 ≠ 一笔交易 | 一个Pair = 一笔完整交易 |
| 离场判断 | 需外挂止盈逻辑 | 下一段反向Pair诞生 = 天然离场 |

直觉上：**Sig告诉你"此刻是什么"，Pair告诉你"这一段趋势是什么"。** 交易赚的是趋势的钱，所以策略单元必须是"趋势段"，而不是"某一瞬间"。

### 1.2 一笔交易 = 一个Pair

Pair天然对应一笔交易，因为它自带交易的三要素：

```
   起点(pair_start)           终点(pair_end)
      │                          │
      ▼          方向=多/空       ▼
  ────●══════════════════════════●────►  时间
      入场                       离场
      （趋势诞生）            （反向趋势诞生）
```

- **起点** = 入场时机的参照
- **终点** = 离场时机（下一段反向趋势诞生的那一刻）
- **方向** = 做多还是做空

这就是为什么代码里 `_compute_strategy_pnl` 的核心是一句 `for pair_start, pair_end in all_pairs`——**循环一次 = 消费一个Pair = 走完一笔交易**。用Pair做单元，"识别趋势"和"何时离场"这两件事被一次性解决，不需要额外的止盈规则。

**这正面回应了你的第2条意见**：策略单元应是多空对，而非瞬时Sig。

## 二、多空对的生命周期

### 2.1 Pair的诞生、存活、合并、终止

Pair的状态机来自底层 `_schmitt_trigger`（施密特触发器）的一个关键设计——**进场严、持有松**的非对称迟滞：

```
       ┌──────────┐   加速度+速度 同时同向(严)   ┌──────────┐
       │  观望 0   │ ─────────────────────────► │ PAIR_BORN │
       └──────────┘                             │  诞生     │
            ▲                                    └────┬─────┘
            │                                         │ 加速度不强烈反向即可维持(松)
            │ 加速度反向(单条件即可)                    ▼
       ┌────┴─────┐                             ┌──────────┐
       │ PAIR_END │ ◄────────────────────────── │PAIR_ALIVE│
       │  终止     │      趋势走完                 │  存活     │
       └──────────┘                             └──────────┘
```

- **诞生（与门，门槛高）**：加速度和速度必须同时同向，才允许一个新Pair诞生。这挡住了大量假启动。
- **存活（或门，门槛低）**：只要加速度不强烈反向，Pair就继续存活。这让趋势能"长出来"。
- **合并**：趋势中间短暂的观望（`+1, 0, +1`）会被合并成一段连续Pair，不会被撕成两个。这是Pair抗噪的结构性来源。
- **终止**：±1永不直接跳到∓1，中间必须经过0，所以异号段之间总隔着零，多空对天然分离。

### 2.2 一个关键的代码事实（务必记住）

**当前 `_find_all_pairs` 根本不返回半边Pair。** 它的配对循环写的是 `range(len(merged) - 1)`——只遍历到倒数第二段。这意味着**每个Pair都必须有一个"下一段反向信号"来收尾**才会被返回。窗口最右侧那个正在延伸、还没等到反向信号的段（就是"半边Pair"），永远不会被写进结果。

由此推出一条贯穿全文的主线：

```
入场点 entry_idx = pair_end = 旧Pair终点 = 新趋势的诞生点
                                  │
                                  ▼
      系统在"旧趋势死、新趋势生"的那一刻，顺着新趋势方向入场
```

`pair_end` 有**双重身份**：它既是上一段Pair的终点，又是下一段趋势的起点兼入场点。后果是——**系统永远慢一个趋势**：它只交易"已经确认结束的趋势的下一段"，当前正在走的这段趋势的利润被整段放弃。

这不是bug，而是一个保守选择：用"滞后一段趋势"换取"对假信号零暴露"。但它也正是你第3条意见要解决的痛点——**半边Pair的处理，本质就是让系统能参与"当前正在进行的趋势"，而不是干等趋势走完。**

### 2.3 窗口滑动如何影响Pair

回测每前进1根K线，底层会在新窗口上重算全部信号。但重算虽是全局的，**只有最右侧"边缘区"（宽度约2-5根K线）的Sig才有实质翻转可能**，窗口深处的信号早已锁定。所以Pair受到的影响有4种场景：

| 场景 | 触发条件 | 概率(SMA) | 对已锁定仓位的影响 |
|------|----------|-----------|--------------------|
| **A 延长** | 半边段同向继续延伸 | ~70-80% | 无（发生在未承认的半边区） |
| **B 缩短/反转** | 边缘1根K线翻成异号 | ~5-10% | 无（只动右端，起点锁定） |
| **C 消失** | 边缘多根K线同时归零 | ~2-5% | **有（幽灵交易风险）** |
| **D 分裂/合并** | 边缘冒出异号K线 | ~3-8% | 少数情况有 |

**贯穿性结论**：无论哪种场景，**Pair的左端（起点，位于窗口深处）绝对稳定，全部不确定性被压缩到最右侧的右端（pair_end）**。这就是"Pair优于Sig"的结构根据——噪声只能动右端，动不了已锁定的左端。而场景C（消失）是唯一危险的一种，它正是半边Pair提前入场的最大风险源，下面第三章详谈。

## 三、半边Pair——最棘手的问题

### 3.1 什么是半边Pair

半边Pair = 窗口最右侧、正在进行、**有头无尾**的多空对。它已经有了起点（趋势已诞生），但还没等到终点（反向信号还没出现）。

```
   已完成Pair                       半边Pair
  ●═══════════●   ●═══════════●   ●═══════════▶ ???
  起   →   终     起   →   终     起   →   当前帧（还在走）
   （在all_pairs里）              （不在all_pairs里，右边缘）
```

因为没有"下一段"来收尾，它被 `range(len(merged)-1)` 排除在外，当前系统对它视而不见。

### 3.2 为什么半边Pair重要

**在实盘中，你当下能交易的那段趋势，永远是半边Pair。** 已完成的Pair都是历史。如果只交易完成Pair，就等于永远等趋势走完才承认它，然后去交易它的"下一段"——**天然滞后整整一个趋势**。

这就是第2.2节说的"永远慢一个趋势"的根源。要及时参与趋势，就必须直面半边Pair。这直接回应你的第3条意见。

### 3.3 半边Pair的三种命运

半边Pair往后会走向三种结局，而**当前系统对"消失"这种假信号的代价恰好是零**（因为从没入场）：

| 命运 | 含义 | 概率(SMA) | 当前系统的代价 |
|------|------|-----------|----------------|
| **成长** | 趋势继续延伸，仍无反向 | ~70-80% | 放弃了这段利润 |
| **完成** | 出现反向段，收尾为完成Pair | ~15-20% | 下一帧才承认、才交易（滞后） |
| **消失** | 起点附近归零，整段蒸发（假信号） | ~5-10% | **零**（幸而从未入场） |

矛盾就在这张表里：**"成长+完成"占85-90%（放弃了利润），但"消失"占5-10%（假信号）。** 要不要提前上车，本质是拿"多赚85-90%情况下的趋势前半段"去赌"5-10%的假信号风险"。这个赌局值不值，取决于我们能否给半边Pair打一个可靠的分。

### 3.4 半边Pair的可靠性评分

用6个指标加权，给半边Pair打一个0~1的分数。分越高，越像"真趋势"而非"即将消失的假段"。好消息是：其中4个指标当前代码已有全部原料，只有跨周期确认需要新建：

| 指标 | 高可靠的样子 | 权重 | 代码可得性 |
|------|--------------|------|-----------|
| **持续时间** | 已持续≥5根K线 | 0.20 | 现成（施密特返回时长） |
| **Sig纯度** | 段内没有中间的0 | 0.15 | 现成（扫一遍即得） |
| **高周期同向** | C周期同向锁定 | **0.25** | 需新建（唯一的新基建） |
| **速度方向稳定** | v与Pair同向且稳 | 0.15 | 现成 |
| **预测曲线方向** | 抛物线外推与Pair同向 | 0.15 | 现成 |
| **起点离边缘** | 起点已越过死区、锁定 | 0.10 | 现成 |

评分公式（概念形式）：

```
可靠性 = 0.20·持续时间 + 0.15·纯度 + 0.25·高周期同向
       + 0.15·速度 + 0.15·预测 + 0.10·起点离边缘
```

设计要点：
- **高周期同向权重最高（0.25）**：这是最强的可靠性来源。"B的半边 + C的完整同向锁定"几乎能排除假信号（详见第六章）。
- **持续时间 + 起点离边缘**：共同保证"段已够长、起点已越过死区"，直接压制"消失"命运的概率。
- **阈值 `REL_TH`** 建议0.6（保守）~0.5（激进），作为回测超参调优。

### 3.5 三种处理模式

打完分后，用哪种模式处理半边Pair，由配置一键切换，默认最保守：

| 模式 | 行为 | 风险/收益 | 适用 |
|------|------|-----------|------|
| **A 保守（默认，=当前代码）** | 不碰半边，只在完成Pair入场 | 零假信号暴露，但滞后一段 | 回测验证、保守交易者 |
| **B 条件入场** | 可靠性≥阈值时，当前帧就上车 | 暴露"消失"风险，靠止损+退出兜底 | 实盘参与趋势 |
| **C 观察补仓** | 半边期只标记不下单；待完成且方向验证后，在后续同向Pair放大仓位 | 高胜率低频，最兼容现状 | 追求胜率的低频交易者 |

**默认模式A = 当前代码逐字节复现**，保证零回归。这是"增量叠加、可独立开关"的落地方式。

## 四、入场机制

### 4.1 两种入场语义

| 维度 | 语义A：完成Pair入场（现状） | 语义B：半边Pair入场（你的诉求） |
|------|----------------------------|--------------------------------|
| 入场点 | pair_end（下一反向段起点） | 当前帧（半边段进行中） |
| 方向 | 新反向趋势方向 | 当前正在走的趋势方向 |
| 本质 | 赌旧趋势死、新趋势生的反转 | 参与当前正在延伸的趋势 |
| 时序 | 永远滞后一整段趋势 | 与趋势同步 |
| 假信号暴露 | 零 | 直接暴露（~5-10%） |

**一个统一视角**：语义A其实是语义B的特例。语义A的入场点 `pair_end` 同时是"新半边Pair的诞生点"——所以语义A本质就是"在半边Pair的第0根K线入场，但用完成对确认了前段结束"。二者只是"入场时机"不同：

- 语义A：等前段完成 → 在新半边段的**第0根**入场；
- 语义B：不等前段完成 → 在当前半边段的**第k根**（进行中）入场。

因此二者能共用同一套方向、预测、退出逻辑，只在"入场触发条件"上分叉，且互不排斥（同一帧最多持一仓）。

### 4.2 入场决策流程

```
无仓状态，每帧判定：
  ┌─────────────────────────────────────────────┐
  │ 1. 完成Pair到达？(pair_end == 当前帧)          │
  │      且 C周期方向不反 → 【语义A入场】(优先)     │
  ├─────────────────────────────────────────────┤
  │ 2. 存在半边Pair？                              │
  │      且 模式==B                                │
  │      且 可靠性 ≥ 阈值                           │
  │      且 C周期同向 → 【语义B入场】               │
  ├─────────────────────────────────────────────┤
  │ 3. 模式==C：标记待补仓，完成后加仓              │
  ├─────────────────────────────────────────────┤
  │ 否则 → 空仓等待                                 │
  └─────────────────────────────────────────────┘
```

原则：**"完成Pair入场"优先于"半边入场"**（前者确定性更高）；半边入场必须同时过"可靠性门"和"C周期同向门"两道关。

## 五、退出机制（三种 + 优先级）

现有退出只有两条：保护期止损（仅入场初期生效）+ Sig反转止盈（全程）。你的第4条意见要求补齐——趋势偏离过大退出、进入下一Pair退出。本版给出**三种退出 + 明确优先级**。

### 5.1 退出①：进入下一个多空对（趋势反转退出，全程生效）

当前Pair结束、新反向Pair诞生时退出：

```
做多持仓 + 新做空段诞生 → 退出
做空持仓 + 新做多段诞生 → 退出
```

**关键改进——N_confirm缓冲**：边缘区单根K线有5-10%概率是噪声翻转（第2.3节场景B）。现有逻辑遇到单个反向K线就退，容易被假反转骗出场。本版要求新反向段**持续N_confirm根（默认2根）才确认**：

```
反向连续根数 reverse_run ≥ N_confirm  → 确认进入下一Pair，退出
```

代价：确认期回吐1-2根利润。收益：避开边缘噪声的假止盈。`N_confirm=0` 时退化为现有行为。这正面回应你第4条中"进入下一个多空对"的退出诉求。

### 5.2 退出②：趋势偏离过大（全程生效）

用预测轨道（抛物线拟合）衡量实际价格偏离预测的程度，超阈值即"趋势破位"退出：

```
偏离度 = |实际价格 - 预测价格| / 预测价格
偏离度 > MAX_DEV_PCT (默认 3%~5%) → 退出
```

**只惩罚"不利偏离"**：做多时，只有价格**跌离**上升轨道才退出；价格涨超预测是有利偏离，让利润继续奔跑。做空反之。

**与现有"保护期止损"的本质区别**（这是关键，二者互补不冲突）：

| | 现有保护期止损 | 新增趋势偏离退出 |
|---|---|---|
| 生效区间 | **仅入场初期**（前n_extend根） | **整个持仓期** |
| 判定 | 单边击穿轨道 | 双向绝对偏离超阈 |
| 语义 | 入场初期防"进错方向" | 全程防"趋势破位/加速失效" |

保护期止损管前期，趋势偏离退出接管后期，覆盖了整个持仓周期。这正面回应你第4条中"趋势偏离过大"的退出诉求。

### 5.3 退出③：上级周期否定（协同退出，全程生效）

C周期活跃Pair翻向、与当前持仓反向 → 强制退出。这是最高优先级的"大势否定"（详见第六章）。

### 5.4 退出优先级

同一根K线上多个条件同时满足时，按"风险紧迫度"降序，命中即离场：

```
优先级                    退出原因            语义
────────────────────────────────────────────────────────
1 (最高)  上级周期否定    higher_tf_veto    大势已反，立即离场
2         趋势偏离过大    trend_deviation   本级趋势破位，价格脱轨
3         进入下一Pair    next_pair         本级正常反转（需N_confirm）
4 (最低)  保护期止损      stop_loss         入场初期防错方向
```

理由：①③是"趋势判断被推翻"（结构性），必须先于②"价格脱轨"和④"初期止损"。实现上在扫描循环内按此顺序 if-elif 判定。

## 六、多周期Pair协同

沿用 A<B<C<D 周期门控，但**门控单元从Sig升级为Pair**。交易在B周期发生，C周期做方向约束，D周期做背景过滤。

### 6.1 C周期方向如何约束B周期

C周期永远站在右边缘，它的"当前方向" `dir_C` = C的半边Pair方向（若有），或C最近完成Pair的方向。门控规则：

| B信号 | C状态 | 决策 |
|-------|-------|------|
| B半边同向 | C同向锁定 | **允许模式B入场**（可靠性大幅提升） |
| B半边同向 | C无同向/反向 | 降级为等待完成，或不入场 |
| B完成Pair | C同向 | 正常入场（现有路径 + C加持） |
| B完成Pair | C反向 | **否决入场**（逆大势） |
| 持仓中 | C翻向反向 | 触发**退出③（上级否定）** |

### 6.2 C的完整同向Pair是打开B半边入场的钥匙

这是协同的核心逻辑：

```
   B半边单独看：假信号概率 5-10%（不敢提前上车）
        +
   C周期完整同向Pair锁定
        ↓
   假信号概率被压到接近 0  → 此时值得提前上车
```

B单独的半边不确定，但"B半边 + C完整同向锁定"两个独立周期的共振，几乎排除了假信号。反之，C不背书就退回保守的等待完成。这就是可靠性评分里"高周期同向"权重最高（0.25）的原因。

## 七、完整决策流程（每帧执行）

```
┌───────────────────────────────────────────────────────────┐
│ 每帧 i（回测推进 / 实盘 tick）                              │
└──────────────────────────┬────────────────────────────────┘
                           ▼
        ┌──────────────────────────────────────────┐
        │ 计算各周期信号: sig_B, sig_C, sig_D        │
        │ all_pairs_B = 完成Pair列表                 │
        │ half_B      = 当前半边Pair（新增）         │
        │ dir_C       = C周期当前方向（新增）        │
        └───────────────┬──────────────────────────┘
                        ▼
              ┌──────────────────┐
              │  当前是否持仓?     │
              └───┬──────────┬───┘
             无仓 │          │ 有仓
                  ▼          ▼
   ┌──────────────────┐   ┌────────────────────────────────┐
   │  入场判定          │   │  退出判定（按优先级 if-elif）    │
   ├──────────────────┤   ├────────────────────────────────┤
   │ 1.完成Pair到达?    │   │ ① 上级否定: dir_C反向? →EXIT    │
   │   且dir_C不反      │   │ ② 趋势偏离: 偏离>阈值? →EXIT    │
   │   →语义A入场       │   │ ③ 下一Pair: 反向run≥N? →EXIT   │
   │ 2.half_B存在?      │   │ ④ 保护期止损: 初期击穿? →EXIT   │
   │   模式B且可靠≥阈    │   │ 否则 → 继续持有                  │
   │   且dir_C同向      │   └────────────────────────────────┘
   │   →语义B入场       │
   │ 3.模式C:标记待补仓  │
   │ 否则 →空仓等待      │
   └──────────────────┘
                  │
                  ▼
         记录交易 / 更新PnL曲线
```

原则：无仓时"完成Pair入场"优先于"半边入场"；有仓时退出按第5.4节优先级；同一帧只持一仓（单持仓模型，与现有代码一致）。

## 八、实战走查（5个Pair级场景）

### 场景1：完成Pair标准入场（模式A）

B周期一段做空趋势走完，出现反向做多段——旧空Pair收尾，`pair_end` 到达。C周期此时也是做多方向。系统在 `pair_end` 顺着新做多方向入场。这是当前代码的标准路径，确定但滞后：做多趋势的第一段其实已经错过。

### 场景2：半边Pair条件入场（模式B）

B周期出现一个正在延伸的做多半边Pair：已持续6根K线（>5）、段内无0（纯度满）、预测曲线向上、起点已离边缘——本级可靠性0.55。此时查C周期：C正好是完整做多Pair锁定（高周期同向=1），总可靠性冲到0.7 > 阈值0.6。系统**当前帧就入场做多**，比场景1提前了整整一段趋势上车。

### 场景3：趋势偏离退出

延续场景2的做多持仓。走了若干根后，价格突然跌离上升预测轨道，偏离度达到6% > 阈值5%。这是全程生效的退出②，判定"趋势破位"，立即离场。注意：此时可能还没出现反向Sig（退出①还没触发），但趋势偏离先一步保护了利润。这正是"全程生效"相对"仅初期生效的保护期止损"的价值。

### 场景4：进入下一Pair退出

做多持仓正常运行，某帧出现一根反向做空Sig。系统不急着退——等N_confirm=2根确认。第2根仍是做空，确认新做空Pair诞生，触发退出①（next_pair），顺势止盈离场。如果第2根又变回做多（假反转），则不退出，避开了边缘噪声骗出场。

### 场景5：半边Pair消失（模式A避免了损失）

B周期出现一个做多半边Pair，但它的可靠性只有0.4（持续时间短、起点还在边缘区）。在模式A下系统不入场。下一帧，边缘区多根K线归零，这个半边段整段蒸发（"消失"命运，~5-10%概率）。因为从未入场，**代价为零**。这说明：可靠性门 + 默认保守模式，天然过滤了假信号——只有在模式B且可靠性够高时才会承担这种风险。

## 九、与现有系统的集成

设计遵循"增量支路 + 默认关闭"，`_find_all_pairs` 对外行为完全不变，保证现有回测零回归。

**新增4个函数**：

| 函数 | 职责 |
|------|------|
| `_merge_segments` | 抽出现有配对逻辑的公共部分，供新旧共用 |
| `_find_current_half_pair` | 识别右边缘的半边Pair |
| `_half_pair_reliability` | 6指标加权评分 |
| `_get_higher_tf_direction` | 跨周期方向，复用现有对齐基建 |

**修改3处**（均向后兼容）：
1. `_find_all_pairs`：内部改用公共函数，**对外返回值逐字节不变**。
2. `_compute_strategy_pnl`：新增半边入场支路 + 三级退出，全部新参数有默认值，`模式A` 时复现现状。
3. 预测曲线生成：为半边Pair也生成一条预测曲线，供方向判定与趋势偏离退出复用。

**默认 `half_pair_mode="A"`** → 所有新支路短路，输出与当前完全一致。"策略A基线不回归"是第一道验证。

## 十、方案优势与实施路线

### 10.1 方案优势

- **正面回应4点意见**：细节层面用Pair替代Sig、专门处理半边Pair、补齐三级退出机制、明确进入下一Pair的退出。
- **零回归**：默认关闭，`_find_all_pairs` 语义纯净不受污染。
- **可量化验证**：逐层开关，独立回测每层的边际贡献（胜率/回撤/夏普）。
- **半边Pair升级为一等公民**：从"永不被交易的盲区"变为"可评分、可门控、可退出"，让策略参与当前趋势而非永远滞后。

### 10.2 实施优先级

| 阶段 | 内容 | 说明 |
|------|------|------|
| **P0（MVP）** | 完成Pair入场 + 进入下一Pair退出 + 趋势偏离退出 | 不碰半边，先补齐退出机制 |
| **P1** | 半边Pair识别 + 可靠性评分 + 模式B条件入场 | 让策略能提前上车 |
| **P2** | 多周期协同（C约束B）+ 上级否定退出 | 用C为B的半边背书 |
| **P3** | 模式C观察补仓 | 高胜率低频路径 |

### 10.3 MVP（最小可行）

**先做：完成Pair入场（现状保留）+ 进入下一Pair退出（带N_confirm）+ 趋势偏离退出。**

这三件事不依赖半边Pair和跨周期基建，改动最小，却已把"退出机制不完整"这个最痛的问题解决掉。半边Pair入场（模式B）和多周期协同作为第二步叠加，每一层都能独立回测、量化增益，稳扎稳打。
