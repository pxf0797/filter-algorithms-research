# B周期同向门控交易方案

> 基于 A/B/C/D 四级周期模型的多周期协同交易判定机制

## 一、问题背景

### 1.1 当前系统的信号困境

在多周期滤波交易系统中，每个周期独立产生 Schmitt 触发信号（Sig）。信号本身经过滞回确认，已经具备一定的抗噪能力。然而，单一周期的信号仍然存在两个根本性问题：

**问题一：信号边缘区的不稳定性。** 趋势滤波算法（Savitzky-Golay、Butterworth 等）在时间窗口的首尾存在边界效应。窗口最右侧的几个 bar 的滤波值尚未经过足够的历史数据"锚定"，Sig 可能在这些 bar 上反复跳变。回测中表现为：同一段行情，回看时信号清晰，但实盘推进时信号闪烁——今天看是 +1，明天数据更新后变成了 0 甚至 -1。

**问题二：小周期信号的"孤岛效应"。** B 周期（如 60 分钟线）发出的做多信号，可能只是大趋势中的一次技术性反弹。如果日线级别（C 周期）正处于明确的下跌趋势，这个做多信号几乎注定失败。单一周期信号缺少来自更大时间框架的"趋势上下文"。

这两个问题叠加，导致纯依赖 B 周期 Sig 的交易决策，在回测中看似有效，实盘却频繁止损。

### 1.2 解决思路

核心思想一句话：**B 周期的交易信号，只有在得到上级周期（C 或 D）的同向确认后才生效。**

直觉类比来自多时间框架分析（MTF）的经典原则——"大周期定方向，小周期找入场"：

- **60 分钟线说"涨"（B），日线也说"涨"（C）** —— 大小周期共振，B 的做多信号有日线趋势作为"靠山"，可信度高。✅
- **60 分钟线说"涨"（B），日线却说"跌"（C）** —— B 在做逆大趋势的无谓反弹，日线的空头压力会压制任何小周期的多头尝试。❌
- **60 分钟线说"涨"（B），日线无明确方向（C=0），但周线 PnL 在涨（D）** —— C 在观望不意味着趋势不存在，更长周期的数据支持做多方向。✅

这不是简单地用 C 替换 B，而是让 C 充当 B 的"过滤器"——B 仍然负责精确的入场时机，但入场的前提是方向得到上级周期的背书。

## 二、周期模型

### 2.1 A/B/C/D 定义

系统的 4 个视图各自独立选择一个周期。不论用户在 UI 上如何排列视图，系统按 `ALL_TFS` 中从精细到粗糙的索引排序，得到 A < B < C < D：

| 角色 | 含义 | 示例配置1 | 示例配置2 |
|------|------|-----------|-----------|
| A | 最精细周期，仅观察 | 15 分钟 | 5 分钟 |
| B | **唯一交易决策周期** | 60 分钟 | 15 分钟 |
| C | B 在 4 视图中的最近上级 | 日线 | 60 分钟 |
| D | 最粗糙周期，兜底确认 | 周线 | 日线 |

排序规则：`A = 索引最小, D = 索引最大, B和C = 中间两个升序排列`。

例如，若用户在 4 个视图中分别选择了 `[日线, 15分钟, 周线, 5分钟]`，对应索引为 `[4, 2, 5, 1]`，排序后 `[1, 2, 4, 5]`，则 A=5分钟、B=15分钟、C=日线、D=周线。

**关键约定：**
- A 仅用于观察盘中微结构，不参与任何交易决策。
- **B 是唯一交易周期**——所有的买卖判断都在此周期执行，包括入场和离场。
- C 是主确认周期，通过 Sig 信号同向判断提供趋势确认。
- D 是兜底确认周期，仅在 C 不可用或 C 不确认时才启用。

> 注意：B 和 C 之间的"紧邻"关系通过 `TF_HIERARCHY` 映射表确定，但方案不强制 C 必须是 B 的紧邻上级。C 只是 4 个视图中可用的、比 B 更粗糙的最近周期。

### 2.2 为什么选 B 作为交易周期？

| 周期 | 适合做什么 | 不适合做什么 |
|------|-----------|-------------|
| A（如 15分钟） | 观察盘中微结构、识别局部支撑阻力 | 交易——噪声太多，信号闪烁频率高，交易成本占比大 |
| **B（如 60分钟）** | **交易决策**——在时效性和趋势稳定性之间取得平衡 | — |
| C（如 日线） | 方向判断——提供可靠的趋势级别信号 | 交易——响应太慢，进场点位严重滞后 |
| D（如 周线） | 大方向背景——判断牛市还是熊市 | 交易——严重滞后，一个信号可能跨越数月 |

B 是"能看到趋势但又不会太慢"的中间层。它比 A 有足够的趋势识别能力，同时比 C/D 有更快的响应速度。

## 三、"同向"的精确定义

方案定义了两种"同向"判断方式，分别用于不同的周期对。

### 3.1 主判断：Sig 信号同向（B 与 C 之间）

**定义：** B 周期与 C 周期的 Schmitt 触发信号值相同。

```
B与C同向做多  ⇔  B.Sig = +1  且  C.Sig = +1
B与C同向做空  ⇔  B.Sig = -1  且  C.Sig = -1
```

**为什么用 Sig 而不是价格方向？**

Sig 已经经过了完整的滞回（hysteresis）确认流程：速度和加速度的 EWMA 平滑、eps 动态阈值计算、基于滞回区间的状态切换。C 的 Sig=+1 意味着日线级别的速度和加速度都确认了上升趋势——这比单纯看"价格涨了"要可靠得多。

Sig 同向判断的优势：计算轻量（仅需 C 的滤波价格和导数数据），C 视图不需要开启 strategy 模式，也不会引入 PnL 曲线的历史依赖。

### 3.2 补充判断：PnL 方向同向（D 专用）

**定义：** D 周期的 PnL 曲线近期方向。具体而言，取 D 周期做多 PnL 曲线最近 N 个 bar（默认 10 个），进行线性拟合，若斜率为正且曲线值大于阈值（100.0），则判定 D 方向做多。若多空曲线都在涨，取绝对值更高的一方作为方向。

**为什么 D 用 PnL 而不是 Sig？**

D（如周线）之上通常没有更高周期来做 Sig 对齐——即使有（如月线、季线），也不在 4 个视图之内。因此 D 需要一个"自包含"的方向判断。PnL 曲线的近期斜率恰好提供了这个能力：PnL 在涨，说明策略在这个周期级别上是有利可图的，间接反映了市场方向的正确性。

PnL 方向判断的局限：PnL 随回测窗口变化，有滞后性（是历史累积结果而非即时判断），且需要 D 开启 strategy 模式。但这些局限在 D 的"兜底"角色中是可以接受的——D 只需要回答"大方向对不对"，不需要精确的入场时机。

### 3.3 同向判断的层级关系

```
         ┌──────────┐
         │  D 周期   │  ← PnL方向同向（兜底）
         │ (周线)    │     仅当C不确认时启用
         └─────┬────┘
               │ C=-1或C=0时启用
         ┌─────┴────┐
         │  C 周期   │  ← Sig信号同向（主确认）
         │ (日线)    │     首选判断依据
         └─────┬────┘
               │ 必须通过
         ┌─────┴────┐
         │  B 周期   │  ← 交易决策周期
         │ (60分钟)  │     所有买卖在此执行
         └──────────┘
```

判断的决策优先级：**C 优先于 D**。C 比 D 更接近 B 的周期粒度，其信号在时间尺度上与 B 形成更紧密的共振。D 的角色是"兜底"而非"覆盖"——只有当 C 不可用或 C 不确认（Sig=0 或 Sig=-1）时，门控才会去问 D。

这引出了一个重要的设计决策：**当 C=+1（确认做多）时，无论 D 说什么，门控直接通过。** 因为：
- C 确认本身已经足够——C 是比 B 更可靠的周期。
- 如果要求双重确认（C+D），会把大量有效信号也过滤掉。
- D 的数据粒度更粗，与 B 的关联度更低，不应该成为否决 C 的因素。

## 四、门控决策逻辑

### 4.1 总体架构（四步决策）

门控函数 `validate_b_trade_long()` 执行四个有序步骤：

```
输入: B.Sig, B.边缘区?, C.Sig, D.PnL方向, C可用?, D可用?

Step 0 — B 自身边缘区检查
  ├─ B 在边缘区 → ⚠️ PENDING（等下一轮 bar 推进）
  └─ B 不在边缘区 → 继续

Step 1 — B 方向检查
  ├─ B.Sig ≠ +1 → ❌ INVALID（B 不看多，没必要确认）
  └─ B.Sig = +1 → 继续

Step 2 — C 周期同向检查
  ├─ C 不可用 → 跳过到 Step 3
  ├─ C.Sig = +1 → ✅ VALID（B 与 C 同向）
  └─ C.Sig ≠ +1 → 跳过到 Step 3（C 不确认，试探 D）

Step 3 — D 周期兜底检查
  ├─ D 不可用 → ⚠️ UNCERTAIN（无上级可参考，保守不交易）
  ├─ D.PnL方向 = 做多 → ✅ VALID（C 不支持但 D 确认）
  └─ D.PnL方向 ≠ 做多 → ❌ INVALID（C 和 D 都不支持）
```

做空是上述流程的方向镜像：将 `B.Sig = +1` 替换为 `B.Sig = -1`，`C.Sig = +1` 替换为 `C.Sig = -1`，`D.PnL方向 = 做多` 替换为 `D.PnL方向 = 做空`。B 的边缘区判断保持不变——无论做多做空，边缘区的信号都不触发交易。

#### 真值表的设计要点

1. **C=0（观望）不否决。** C 在观望不意味着趋势不存在——震荡市中 C 常常在 0 徘徊，但更大级别的趋势可能已经确立。门控将决策权交给 D。

4. **保守的不确定。** 第 8 行：当 C 和 D 都不可用时，返回 UNCERTAIN，不交易。没有上级确认的单向信号，噪声概率高。

## 五、边界情况处理

### 5.1 B 在边缘区（PENDING）

窗口尾部 `edge_width` 个 bar（默认 5 个）内的 B.Sig 标记为 PENDING——不触发交易，等待下一轮 bar 推进后重新评估。

这对应于回测中的经典问题：窗口推进前后，同一个 bar 的 Sig 可能从 +1 变为 0。边缘区判断通过"不交易"的保守策略回避了这个风险，代价是延迟 2-3 个 bar 的入场。考虑到 B 周期通常为 60 分钟级别，这个延迟在可接受的范围内。

### 5.2 C 在边缘区

C 即使位于边缘区，其 Sig 值仍被使用。理由：C 的精度需求低于 B——C 只需要提供方向信号，不需要精确的入场时机。即使 C 在边缘区 Sig 不够"坚定"，其方向信息仍优于完全不可用。如果 C 的边缘区 Sig 确实出错了（与 D 矛盾），门控自然会在 D 兜底阶段发现并纠正。

### 5.3 C 和 D 矛盾

当 C 和 D 的方向判断不一致时：**以 C 为准。**

- 如果 C=+1（确认做多）且 D=做空：C 确认通过，门控返 VALID，不检查 D。
- 如果 C=-1（看空）且 D=做多：D 的做多覆盖了 C 的反向，门控返 VALID（真值表第 4 行）。这里的逻辑是：C 没有确认做多（它看空），所以门控进入 D 兜底，而 D 支持做多，所以通过。

### 5.4 数据缺失的回退链

```
B 数据缺失 → 无法交易（根本无信号来源）
C 数据缺失 → 降级到 D 判断
D 数据缺失 → 只有 B+C 判断（无兜底）
C 和 D 均缺失 → ⚠️ UNCERTAIN（保守不交易）
```

## 六、实战走查

以下走查中，Sig 值来自 Schmitt 触发器（+1 做多 / 0 观望 / -1 做空），D.PnL方向来自 D 周期的 PnL 曲线近期斜率。

### 场景 1：标准共振做多 ✅

```
B (60分钟):  Sig = +1, 已锁定, 边缘区外
C (日线):    Sig = +1
D (周线):    PnL方向 = 做多

判定路径: B.Sig=+1 → C可用 → C.Sig=+1 → ✅ VALID
操作: B周期可执行做多。
解读: 60分钟、日线、周线三者一致看多——大小周期共振，这是最可靠的信号。
```

### 场景 2：B 看多但 C 看空 ❌

```
B (60分钟):  Sig = +1, 已锁定
C (日线):    Sig = -1
D (周线):    PnL方向 = 做空

判定路径: B.Sig=+1 → C可用 → C.Sig=-1 → 查D → D.PnL方向=做空 → ❌ INVALID
操作: 不做。60分钟在做无谓的反弹，日线和周线都是空头趋势。
解读: B的做多信号是逆大势的小反弹，不值得参与。
```

### 场景 3：C 不确认但 D 支持 ✅

```
B (15分钟):  Sig = +1, 已锁定
C (60分钟):  Sig = 0（观望）
D (日线):    PnL方向 = 做多

判定路径: B.Sig=+1 → C可用 → C.Sig=0 → 查D → D.PnL方向=做多 → ✅ VALID
操作: 做多。虽然60分钟犹豫，但日线趋势向上。
解读: 60分钟级别的震荡让C陷入观望，但日线级别的做多PnL持续上升——更大格局确认了方向。
```

### 场景 4：信号在边缘区 ⚠️

```
B (60分钟):  Sig = +1, 但在窗口最右侧3个bar内（边缘区）
C (日线):    Sig = +1
D (周线):    PnL方向 = 做多

判定路径: B在边缘区 → ⚠️ PENDING
操作: 不交易。等2-3个bar推进后，B的Sig稳定了再说。
解读: 当前Sig可能因边界效应不可靠。保守等待，避免被"闪烁信号"骗入场。
```

### 场景 5：C 和 D 矛盾，C 确认优先 ✅

```
B (60分钟):  Sig = +1, 已锁定
C (日线):    Sig = +1
D (周线):    PnL方向 = 做空

判定路径: B.Sig=+1 → C可用 → C.Sig=+1 → ✅ VALID（不到D）
操作: 做多。C确认足够，D的做空反映更早期的数据。
解读: C的Sig是日线级别的速度和加速度确认——比周线PnL的滞后统计更及时。以更接近B的周期为准。
```

### 场景 6：C 不可用，全靠 D ⚠️ / ✅

```
情况A:
B (15分钟):  Sig = +1, 已锁定
C (60分钟):  不可用（视图未渲染）
D (日线):    PnL方向 = 做多

判定路径: B.Sig=+1 → C不可用 → 查D → D.PnL方向=做多 → ✅ VALID
操作: 做多。唯一的上级周期给出确认。

情况B:
B (15分钟):  Sig = +1, 已锁定
C (60分钟):  不可用
D (日线):    PnL方向 = 做空 或 D也不可用

判定路径: ... → ❌ INVALID 或 ⚠️ UNCERTAIN
操作: 不做。没有上级确认，保守不交易。
```

## 七、与现有系统的集成

### 7.1 数据流

```
┌──────────┐   ┌──────────┐   ┌──────────┐
│ C周期视图  │   │ D周期视图  │   │ B周期视图  │
│ Sig, PnL  │   │ PnL数据   │   │ Sig       │
└─────┬─────┘   └─────┬─────┘   └─────┬─────┘
      │                │               │
      │ session_state  │               │
      │ _pnl_{C}       │               │
      └────────┬───────┘               │
               │                        │
               ▼                        ▼
        ┌──────────────────────────────────┐
        │   validate_b_trade_signal()       │
        │   门控判定函数（新增）              │
        └──────────────┬───────────────────┘
                       │
                       ▼
        ┌──────────────────────────────────┐
        │   _compute_strategy_pnl()         │
        │   仅处理通过门控的有效信号          │
        └──────────────────────────────────┘
```

### 7.2 改动范围

| 文件 | 改动内容 | 说明 |
|------|---------|------|
| `services/filter_engine.py` | 新增 `validate_b_trade_long()` 和 `validate_b_trade_short()` | 门控判定核心逻辑 |
| `streamlit_app.py` | 修改 `_compute_strategy_display()` | 在调用 PnL 计算前插入门控过滤 |
| `state.py` | 新增 `_bt_gating_enabled` 布尔开关 | 门控启用/禁用（用于 A/B 对比回测） |

**不改动的组件：** `_schmitt_trigger`、`_align_pnl_to_current_tf`、`_add_alignment_subplot`、`_compute_holding_masks`——全部原样复用。门控是一个"夹层"，插在信号生成和交易执行之间，不改变上游的滤波链路，也不改变下游的 PnL 计算。

### 7.3 最小侵入集成

门控在集成上追求"最小代码改动"。核心逻辑集中在一个新函数中，集成只需要在 `_compute_strategy_display()` 的入口处增加一个条件判断：

```
进入 _compute_strategy_display()
  │
  ├─ 如果是 B 周期 且 门控开关为 True?
  │    ├─ 是 → 调用 validate_b_trade_signal()
  │    │       ├─ VALID → 继续计算 PnL
  │    │       └─ 其他 → return None（跳过）
  │    └─ 否 → 继续计算 PnL（门控未启用的视图）
  │
  └─ 后续逻辑不变
```

这种设计的好处是：关掉门控开关后，系统行为与改动前完全一致——一个布尔值即可在"有门控"和"无门控"之间切换。

### 7.4 回测对比验证

启用门控后可以直接对比：
- **无门控**：B 周期所有 Sig 信号都交易。
- **有门控**：仅通过门控判定的 B 周期信号交易。

对比指标：胜率、交易次数、最大回撤、Sharpe 比率。预期门控将在减少 30%-50% 交易次数的同时，提升 10%-20% 的胜率。因为被过滤掉的正是那些"B 有信号但上级周期不支持"的低质量交易——它们在回测中贡献了小幅利润但不稳定，在实盘中往往因滑点和手续费变成亏损。

## 八、方案优势与局限

### 优势

- **逻辑透明。** 三步决策——B 自己、C 确认、D 兜底——每一步都有明确的判断标准和失败后的回退路径。不需要"调参黑魔法"或不可解释的机器学习模型。
- **改动最小。** 复用现有的 Sig 计算、PnL 存储、TF_HIERARCHY 映射表和时序对齐函数。不改滤波链路，不新增 UI 控件（第一阶段），不影响其他周期的计算。
- **回退链设计。** 从 C 到 D 到 UNCERTAIN，保证任何数据可用性状态都有明确的结论。不会出现"C 不可用就崩溃"的脆弱性。
- **可开关。** 一个布尔值切换有/无门控，方便 A/B 对比回测。如果回测结果不理想，随时可以关掉回到原始策略。

### 局限

- **交易次数减少。** 门控的本质是过滤——它会筛掉"B 有信号但上级不支持"的交易。这降低了交易频率，可能让一些追求高频交易的策略不适配。
- **依赖上级数据。** C 或 D 周期必须已加载并计算。如果用户未配置 3 个以上视图，门控的回退链会缩短甚至失效。
- **D 周期 PnL 的滞后性。** PnL 是历史累积曲线，对市场方向的反映有延迟。当 D 的 PnL 方向刚刚翻转时，门控可能在短时间给出错误判断。
- **C 在边缘区的 Sig 风险。** 我们选择"仍使用 C 的 Sig"是实用主义折中——宁可接受不完美的上级确认，也不要没有上级确认。但如果 C 的边缘区 Sig 系统性地出错，这会成为门控的精度瓶颈。回测验证阶段需要重点关注这一问题。
