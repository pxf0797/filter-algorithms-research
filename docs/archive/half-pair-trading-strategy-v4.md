# 半边多空对交易策略（v4：断续多空对的质量甄别）

> 起点即入场，C 状态门控，核心在离场，新增断续型多空对甄别

---

## 一、核心认知：永远在操作半边多空对

**一句话：** 不管是回测推进还是实时交易，你永远站在窗口最右边缘，当前正在走的那段多空对永远只有起点、没有终点——这就是"半边"，它不是特殊情况，它是唯一现实。

### 1.1 什么是多空对，什么是"半边"

**多空对（Pair）= 一段连续同向的趋势。** 它由三个要素定义：

| 要素 | 含义 | 来源 |
|------|------|------|
| 起点 | 趋势诞生的那一根 K 线（Sig 从 0 变为 ±1） | Schmitt 触发器状态转移 |
| 终点 | 趋势结束、反向趋势诞生的那一根 K 线 | 下一段反向段的起点 |
| 方向 | +1（多）或 -1（空） | 段内 Sig 的符号 |

起点和终点都有的，就是**完整多空对**；当下正在走、有起点却**没有终点**的这一段，就是**半边多空对**。

```
完整多空对：  起点 ●━━━━━━━● 终点      （历史，已定型）
半边多空对：  起点 ●━━━━━━━▶ ???       （当下，还在走）
```

### 1.2 为什么说"永远"操作半边

无论回测第几帧、还是实时此刻，最右边那个多空对永远是半边——因为"当下"这个位置，天然就是趋势还没走完的地方。今天的半边明天可能走完变成完整对被甩到左边，那时又有**新的**半边出现在最右边。**你操作的对象，永远、且只能是这个半边多空对。**

### 1.3 策略骨架（v4）

**一句话：** 半边起点一出现就入场（靠 C 周期同向背书），入场后唯一要做的是判断怎么离场；v4 在此之上，先甄别这个半边**是不是断续拼出来的**。

```
        永远操作半边多空对
                │
       ┌────────┼────────────────┐
       ▼        ▼                ▼
   起点出现即入场  怎么离场       这半边"实不实"？
   （C同向背书）  = 核心          = 断续质量甄别 ⭐v4新增
```

v4 在 v3（C 五态离场门控）之上，只补一件事：**当半边是 `[+1,0,+1,0]` 这种断续拼接时，识别并给它的质量打折。** v3 及更早版本默认所有半边"纯净"，从不追问它中间被 0 打断过几次。

## 二、入场：起点即判定（不等锁定）

**一句话：** B 半边起点一出现（Sig 0→±1）当帧判入场，唯一门槛是 C 多空对状态 = 强同向。

### 2.1 为什么不等锁定

等锁定 = 好几根 K 线过去 = 趋势已走一大段 = 进场太晚。趋势最值钱的就是起步那一段。思路是：**不用时间换确定性，而用空间（C 周期背书）换确定性**——起点一诞生就判，让上级周期的同向趋势替我们过滤假信号。

### 2.2 入场时机与条件

```
入场 IF:
    B 当前半边起点当帧诞生 (pair_start_B == i)      # 时机：0 延迟
    AND C_pair_state(dir_B, i) == STRONG_ALIGN      # 背书：C 强同向
    [v4 追加]  AND 该半边非"断续型 STRONG"           # 断续质量门（见第四章）
```

- **时机**从"锁定后"提前到"起点当帧"，零延迟吃到趋势起步段。
- **门槛**是"C 强同向"。v4 在这道门后再加一层：C 即便 STRONG，若它是断续抖出来的 STRONG，也要打折（4.6 节）。

### 2.3 不锁定的风险与双重兜底

| 兜底 | 时点 | 机制 |
|------|------|------|
| 兜底① C 强同向确认 | 入场时 | B 单边假信号与"C 已有同向活跃半边"同时出现的概率远低于 B 单独假信号 |
| 兜底② 入场依据消失快速离场 | 入场后 | 起点若在边缘窗口内蒸发，立刻小损离场（`entry_void`），把假起点伤害限制在几根 bar 内 |

## 三、同向判断：看 C 的多空对状态（C 五态）

### 3.1 为什么不看 C.Sig 而看多空对状态

Sig 是瞬时值，一根 K 线就翻；多空对状态反映 C 这一整段趋势的健康度。C.Sig 看不见"C 趋势即将衰竭"这个阶段——C 的 +1 半边已降速或冒出反向苗头时，B 若此刻入场 = 在 C 趋势末端上车。C 周期不是被动提供方向，而是**自己也在操作半边多空对**，B 要判断的是 C 这个多空对**整体处于什么阶段**。

### 3.2 物理事实：C 趋势衰竭是渐进的

Schmitt 触发器永不 +1↔-1 直跳，必经 0；所以 C 转向必先降速→到 0→再反向：

```
   健康奔跑            降速             反向确认
   Sig=+1  ───────▶  Sig=0  ───────▶  Sig=-1(连续N根)
   STRONG_ALIGN      WEAK_ALIGN        MISALIGN
```

**中间态不是硬造的，它是触发器里天然存在的物理阶段。**

### 3.3 C 多空对有两种"结束"方式

C 和 B 一样跑三离场，它的当前半边有两种等价的"结束"：

| 结束方式 | 触发离场 | dir_C 是否翻转 | v2 是否覆盖 |
|---------|---------|--------------|-----------|
| **正常结束** | 离场①：Sig 反向 `reverse_run ≥ N_confirm` | ✅ 翻到 -d_B | ✅ → MISALIGN |
| **提前结束** | 离场②：偏离过大 `signed_dev > MAX_DEV_PCT_C` | ❌ 未翻（仍名义同向） | ❌ **被漏掉** |

两种结束对 B 完全等价——**C 背书消失**。区别只在结束后 C 站在哪里：MISALIGN 是 C 反手站到 B 对面（背书反转）；C_ENDED 是 C 退场观望（背书撤销，dir_C 仍名义同向但已平仓）。

### 3.4 C 周期多空对的五种状态

| 状态 | 精确定义 | C 是否持仓 | 检测条件 | 对 B 入场 |
|------|---------|-----------|---------|-------------|
| **STRONG_ALIGN** | dir_C==d_B，健康奔跑 | ✅ | 无预警且 `signed_dev ≤ WARN_DEV_PCT_C` | ✅ 入场 |
| **WEAK_ALIGN** | dir_C==d_B，露出衰竭前兆但离场②未触发 | ✅ 仍持仓 | `0<reverse_run<N_confirm` 或 `WARN ≤ dev ≤ MAX` 或 [软]Sig→0 | ⚠️ 降级/不入 |
| **C_ENDED** | dir_C==d_B（名义同向）但离场②已触发、已平仓 | ❌ 已平仓 | `signed_dev > MAX_DEV_PCT_C` | ❌ 不入 |
| **MISALIGN** | dir_C == -d_B，反向结束、已反手 | ❌ 已反手 | `reverse_run ≥ N_confirm` | ❌ 不入 |
| **NO_DIRECTION** | dir_C == 0，无活跃非零半边 | ❌ 空仓 | 无当前非零合并段 | ❌ 不入 |

**只有 STRONG_ALIGN 打开入场。** C_ENDED 恰好插在 WEAK（未离场）与 MISALIGN（反向离场）之间，补上"同向离场"缺口——C 结束了、但没反手。关键顺序：**先判 `dev > MAX_DEV_PCT_C`（C_ENDED），再判 WEAK 预警**，确保"已离场"永远优先于"仍持仓预警"。

## 四、断续型多空对：`[+1,0,+1,0]` 的质量甄别 ⭐v4 核心新增

> **先说一句诚实话：** 本章大部分是**真新增**（v1~v3 都没有断续量化）；只有 4.4 节的 N_confirm 是**补落地 v3 早就提出、但代码从未实现**的设计。二者会逐节标注。

### 4.1 什么是断续型多空对

**一句话：** 同一段同向趋势，中间被 0 反复打断再续上，比如 `[+1,0,+1,0,+1]`——它名义上是一段 +1，实则是抖出来的。

C 五态回答"C 这段趋势在哪个阶段"，却默认这段趋势**纯净**。现实里一个半边可能长这样：

```
纯净型：  +1 +1 +1 +1 +1        （一路满速，可信）
断续型：  +1  0 +1  0 +1        （抖抖停停，同样被当作一段 +1）
```

两者当帧都是 +1，C 五态给出**相同**判定，但可靠性天差地别。v4 要把这层差别量化出来。

### 4.2 跨零合并的现状：无 gap 上限 + 非对称性（代码事实）

以下是对 `_find_all_pairs` **逐行实跑**得到的确切规则（非推理）：

- **Step1 收集非零段**：线性扫描，**所有 0 被直接丢弃**，不留任何 gap 长度信息。
- **Step2 跨零合并**：判据**只有一个——符号相同**就合并，完全不看隔了几个 0。
- **Step3 异号配对**：相邻异号段配成 pair。

由此两条已验证的确切规则：

1. **没有 gap 上限。** `[+1,0,0,0,+1]` 隔 3 个 0 仍合并成一段；隔 3 个还是 300 个 0 结果一样——只要中间没有非零反向段。
2. **合并只被"反向非零段"打断，哪怕 1 根。** `[+1,0,-1,0,+1,0,-1]` 中间单根 `-1` 让两个 `+1` 无法合并。

**核心非对称性：同向断续被平滑、异号断续被放大。** 四变体实跑对照：

| 变体 | merged | pairs | 现象 |
|---|---|---|---|
| `[+1,0,+1,0,-1]` | `[(0,2,+1),(4,4,-1)]` | `[(0,4)]` | 同向合并，止于反向入口 |
| `[+1,0,0,0,+1]` | `[(0,4,+1)]` | `[]` | 无 gap 上限，合并成半边 |
| `[+1,0,-1,0,+1,0,-1]` | 不合并 | `[(0,2),(2,4),(4,6)]` | 单根反向碎片化→3 笔 |
| `[+1,0,+1,0,+1]` | `[(0,4,+1)]` | `[]` | 断续被平滑成一段半边 |

```
同向断续 +1,0,+1  ──merge──▶  一段 +1   （被平滑保护 ✅）
异号断续 +1,0,-1  ──打断──▶  两段/碎片  （被放大 ❌）
```

**这段合并逻辑对同向断续友好、对异号断续脆弱，是断续质量问题的根源。**

**⚠️ 澄清（诚实性）：** 有个流传的说法是"v3 用 Sig 纯度作可靠性指标"——**这与 v3 文档不符**。v3 里根本没有"纯度"构件，只有当前帧的**软 decel 预警**（恰好当帧 `sig==0` 才触发、不累计历史）。所以 `[+1,0,+1,0]` 的低纯度在 v3 里**不被任何构件扣分**。v4 才第一次把它量化。

### 4.3 断续度量化（gap_count / gap_ratio）【真新增】

由于 0 在 Step1 就被丢弃，要量化断续必须**先保留 gap 信息**。为每个 merged 段附带两个标量：

| 指标 | 定义 | `[+1,0,+1,0,+1]`（merged=(0,4)） |
|---|---|---|
| `gap_count` | 段内被 0 打断的次数 = 合并子段数 − 1 | 3 子段 → `gap_count=2` |
| `gap_ratio` | 段内 0 根数 ÷ 段总长 | 2 ÷ 5 = `0.4` |

越断续 → 两值越高 → 半边质量越低。这是**唯一需要动 `_find_all_pairs` 数据结构**的改动：Step1 记录每个 0-run 长度，Step2 合并时累加进 merged 段。计算 O(n)、零新数学。它是 4.5、4.6 节的输入地基。

### 4.4 异号断续的 whipsaw 风险 → N_confirm 缓冲【补落地 v3 已有】

**最尖锐的一条。** 代码事实：`_find_all_pairs` 里 pair 的 dir 由 `merged[-1]` 符号决定，**单根反向即翻 dir**；`_compute_strategy_pnl` 用**单根** `sig==-1` 即离场。二者**都无 N_confirm**。于是 `[+1,0,-1,0,+1,0,-1]` 被切成 3 笔碎片、dir 跳 4 次 = 无缓冲 whipsaw。

**这印证了 v3 的 N_confirm 方向正确**：v3 早已假设"dir 只在 `reverse_run ≥ N_confirm` 才翻、离场① 也用 `reverse_run ≥ N_confirm`"——只是代码从未落地。把这道门真正接进去：

```
reverse_run = 连续同向反向"非零"段的累计根数
0 出现 → reverse_run 归零（要求反转不被打断才算数）
仅当 reverse_run ≥ N_confirm 才翻 dir / 触发离场①
```

**为什么恰好治好异号断续：**

```
[+1, 0, -1, 0, +1]   孤立单根 -1 后面是 0
        └ reverse_run=1 →遇0归零→ 永远够不到 N_confirm
        ⇒ 不翻向、不砍仓，whipsaw 被吞掉 ✅

[+1, 0, -1, -1, -1]   连续 -1
           └ reverse_run 累到 N_confirm ⇒ 真反转仍被确认 ✅
```

异号单根本就不该立即翻 dir 或砍仓。默认 `N_confirm=2` 起步，`N_confirm=1` 复现现状。

### 4.5 同向断续：有效起点重定义【真新增】

代码事实：merge 把趋势真正发力的后续 +1 **折回最早起点**（`[+1,0,+1,0,-1]`、`[+1,0,+1,0,+1]` 的起点都锚在 index 0）。v3"起点即入场"会锚到可能是噪声的第一个 +1，且不为真启动生成新 pair_start——**"要么在假起点 index 0 进早，要么错过 index 4 的真启动，二者必居其一"**。

**设计：** 为断续半边定义两个起点，与断续度联动择时：

| 起点 | 定义 | 用途 |
|---|---|---|
| `earliest_start` | 最早 +1（现状锚点，index 0） | 连续型半边用它（早起点可信） |
| `effective_start` | **最近一次 0→+1 的恢复点**（index 4） | 断续型半边入场择时改用它 |

```
gap_count ≤ 阈值(连续型)  → 用 earliest_start（趋势干净，现状）
gap_count >  阈值(断续型)  → 入场择时用 effective_start
                            （早起点大概率是噪声起步，等最近一次重启才进）
```

默认阈值高到不触发 = 用 earliest（复现现状）。

### 4.6 断续对 C 状态的影响：连续型 STRONG vs 断续型 STRONG【真新增】

代码事实：v3 的 C 五态**逐帧无记忆**。对 `[...,+1]` 当帧 sig=+1、dev 低 → 判 STRONG_ALIGN，"这段一路 +1,0,+1 震了很多次"的历史不进入判定。抖 5 次的虚弱趋势与干净强趋势，只要当帧都 +1 且 dev 低，C 状态**完全相同**。

**设计：不新增第 6 态，而是给 STRONG_ALIGN 加断续度调节因子把它细分：**

| STRONG 子型 | 条件 | 对 B 入场 |
|---|---|---|
| 连续型 STRONG | `gap_count ≤ 阈值` | ✅ 满仓（现状） |
| 断续型 STRONG | `gap_count > 阈值`（或 `gap_ratio > 阈值`） | ⚠️ **质量打折**：降级为"收紧入场"（等同 WEAK 谨慎处理 / 减半仓 / 抬高其余门槛） |

逻辑：C 名义 STRONG，但它这段趋势是抖出来的，背书含金量打折，B 不该按满速强同向对待。这把断续历史并入 C 判定，而非只看当前帧。默认阈值高到不触发 = C 判定逐字节复现 v3。

### 4.7 gap 上限（可选，默认关 = 复现现状）【真新增】

现状合并**无 gap 上限**——这是"已正确处理"的一面（抗降速，见 4.2），但极端下"隔 300 个 0 仍合并成一段"未必合理。加超参 `MAX_GAP_BARS`：

```
MAX_GAP_BARS = ∞（默认）→ 永不触发，逐字节复现现状
MAX_GAP_BARS = N（可调） → 两子段间 0-run > N 视为趋势中断，后段另起新 pair_start
```

它与 4.5 的 `effective_start` 是应对"gap 太大"的两种思路（重定义起点 vs 直接断开），留给回测选。**默认关。**

### 4.8 本章诚实边界：哪些是对的，不改

| 项 | 结论 |
|---|---|
| 同向断续合并鲁棒（`+1,0,+1` 稳定合并、抗任意 gap） | ✅ **已对，不改** |
| entry_void 抗短暂降速（挂 pair-dir 时 `[+1,0,+1]` 尾随 0 被吸收） | ✅ **已对（条件性）**，实现钉死"用 pair-dir 非裸 sig"即可 |
| 异号 whipsaw | ❌ 补 N_confirm（v3 已有设计） |
| 断续度不可见 / 真启动丢失 / C 无记忆 / gap 上限 | ❌ 真新增 |

## 五、入场决策表（v4，5 态 × 断续度）

**一句话：** B 半边方向 × C 五态 × **断续度**→ 入场/降级/不入；相对 v3 在 STRONG 行内按断续度再分一层。

| # | B 起点当帧 | C 五态 | 断续度 | 决策 | 原因 |
|---|-----------|--------|--------|------|------|
| 1 | 是 | STRONG_ALIGN | 连续型 | ✅ 入场（满仓） | C 健康背书 + 半边纯净，最可靠 |
| 2 | 是 | STRONG_ALIGN | **断续型** ⭐新 | ⚠️ 收紧入场/减半仓 | C 名义强同向但抖出来的，背书打折 |
| 3 | 是 | WEAK_ALIGN | 任意 | ⚠️ `allow_weak` 开→半仓；关→不入 | C 同向但衰竭中 |
| 4 | 是 | C_ENDED | 任意 | ❌ 不入 | C 多空对已提前离场，背书撤销 |
| 5 | 是 | MISALIGN | 任意 | ❌ 不入 | C 反向结束、反手做空，逆大势 |
| 6 | 是 | NO_DIRECTION | 任意 | ❌ 不入 | C 无背书，B 单边裸奔 |
| 7 | 否 | 任意 | 任意 | — 不判入场 | 仅起点当帧判入场 |

**与 v3 决策表的差异：** 仅新增第 2 行——把 v3 里"STRONG 一律满仓"按断续度切成"连续型满仓 / 断续型打折"。其余行与 v3 完全一致。断续型半边入场时，起点择时改用 `effective_start`（4.5）。

## 六、离场：策略的核心（三种机制 + C 状态梯度响应）

**一句话：** 三离场机制不变，v3 把离场③按 C 生命周期梯度响应；v4 在离场① 补上 N_confirm 缓冲。

### 6.1 三离场机制

| 机制 | 触发 | 说明 |
|------|------|------|
| 离场① 进入下一多空对 | B 反向段 `reverse_run ≥ N_confirm` | 本级正常反转，止盈离场。**v4：接入 N_confirm，异号单根不再即砍**（4.4） |
| 离场② 趋势偏离过大 | B 不利偏离 `> MAX_DEV_PCT_B` | 只看不利方向，破位即走 |
| 离场③ 上级反向（C 状态） | C 状态梯度响应（见 6.2） | 梯度，非一刀切 |
| （保留）entry_void | 边缘窗口内 B 起点蒸发 | 挂 pair-dir，`[+1,0,+1]` 尾随 0 不误触发 |
| （保留）预测保护期止损 | 入场初期击穿轨道 | 防错方向 |

### 6.2 离场③：C 状态梯度响应

```
优1   C == MISALIGN            → 🚪 立即全额离场（战略否定，最高优先级）
优1.5 C == C_ENDED             → ⚠️ 收紧 B 阈值 + 减仓（背书撤销，非强退）
优2   边缘窗口内 B 起点蒸发     → 🚪 entry_void 快速小损离场
优3   B 不利偏离 > MAX_DEV_B    → 🚪 离场②
优4   B 反向段 ≥ N_confirm      → 🚪 离场①（v4：N_confirm 缓冲异号单根）
(保留) 预测保护期击穿轨道       → 🚪 止损
否则                           → 继续持有
```

| C 状态 | B 持仓响应 | 强度 |
|--------|-----------|------|
| STRONG_ALIGN | 继续持有 | — |
| WEAK_ALIGN | 只收紧其余阈值，不减仓 | 轻 |
| C_ENDED | 收紧 + 减仓，剩余交本级①②兜底 | 中 |
| MISALIGN | 立即全额强退 | 强 |

**MISALIGN 强退（C 反手对立）、C_ENDED 收紧减仓（C 退场观望）**——两者都源于"C 结束"，但反手 vs 退场强度不同。

## 八、实战走查（bar 级）

### 场景 1：起点即入场，C 强同向 + 纯净半边 ✅

```
B：新多头半边起点当帧，半边 = [+1,+1,+1]（gap_count=0，连续型）
C：dir_C=+1，signed_dev ≤ WARN → STRONG_ALIGN
判定：起点当帧 ✓ + C STRONG ✓ + 连续型 ✓ → ✅ 满仓入场
```

### 场景 2（v4 新）：C 强同向但半边断续 → 打折入场 ⚠️

```
B：新多头半边起点当帧，半边 = [+1,0,+1,0,+1]（gap_count=2，断续型）
C：dir_C=+1，dev 低 → 名义 STRONG_ALIGN
判定：C STRONG，但断续型 → ⚠️ 收紧入场 / 减半仓；起点择时改用 effective_start（最近一次 0→+1）
解读：v3 会把这当纯 STRONG 满仓进。v4 看出这段 +1 是抖出来的——C 背书含金量打折，
      且早起点 index 0 可能是噪声，宁可等最近一次重启（index 4）再进、且减仓。
```

### 场景 3（v4 新）：异号断续，N_confirm 吞掉 whipsaw ⚠️

```
持仓：多头。后续 Sig = [+1, 0, -1, 0, +1]
v3/现状代码：单根 -1 即离场 → 砍仓，随后 +1 又得重进 = whipsaw
判定（v4）：reverse_run 遇孤立 -1=1，紧跟 0 归零，永不达 N_confirm=2 → 不砍仓，继续持有
解读：异号单根被识别为噪声，不触发离场①。若后续是 [-1,-1] 连续，reverse_run 达标才真离场。
```

### 场景 4：C 转 C_ENDED → 收紧减仓（非强退）

```
持仓：多头，入场时 C 是 STRONG。本帧 C 的 signed_dev 突破 MAX_DEV_PCT_C
     → C 离场②触发、平仓 → C_ENDED（dir_C 仍名义 +1，未反手）
判定：优1.5 C==C_ENDED → ⚠️ 收紧 + 减仓，剩余交本级①②兜底
```

### 场景 5：C 转 MISALIGN → 全额强退

```
持仓：多头，B.Sig 仍 +1。C 的反向段连续 ≥ N_confirm，dir_C 翻 -1 → MISALIGN
判定：优1 C==MISALIGN → 🚪 立即全额离场（压过本级 +1、压过 C_ENDED）
```

## 九、与现有系统集成（含代码现状的诚实说明）

### 9.1 铁律级前提：当前代码 ≠ v3，v1~v3 是设计蓝图

**必须先讲清楚，否则集成会踩空。** 对 `filter_engine.py` 逐行实跑追踪确认：

| 维度 | v3 文档假设 | **当前源码实际** |
|---|---|---|
| 入场点 | pair_start（起点即入场） | **pair_end**（反向入口边缘 + 抛物线方向确认） |
| 离场反转 | `reverse_run ≥ N_confirm` | **单根** `sig==-1` 即离场，**无 N_confirm** |
| C 五态 / signed_dev / reverse_run / entry_void | 核心构件 | **源码里完全不存在**（grep 无） |
| "纯度"构件 | v3 里本就没有 | 源码也没有（0 在 Step1 即丢弃） |

**结论：v1、v2、v3、v4 全是设计蓝图，尚未落地。** 因此 v4 的集成不是"在 v3 代码上加断续章节"，而是**与 v3 一起从蓝图落地**。任何"改动极小、复用 v2 已算值"的措辞，指的是**设计层的复用关系**，不是"代码里已存在只等微调"。

### 9.2 已正确处理的，不改

`_find_all_pairs` 的**同向断续合并**是当前代码里**唯一已经正确兜底**的部分：`+1,0,+1` 稳定合并、对任意 gap 鲁棒、不因降速的 0 把一段趋势拆两段。**这部分无需改。** entry_void 抗降速也已可正确处理（条件性）——只要实现时挂 pair-dir。

### 9.3 改动范围（增量 + 默认复现现状/ v3）

| 改动 | 位置 | 性质 | 说明 |
|------|------|------|------|
| 保留 gap 信息，加 `gap_count/gap_ratio` | `_find_all_pairs` Step1/2 | 真新增 | 唯一动数据结构处；只计算不动决策 = 无影响 |
| dir 判定 + 离场① 接入 `reverse_run ≥ N_confirm` | `_find_all_pairs` / 离场 | **补落地 v3 已有** | `N_confirm=1` 复现现状 |
| `effective_start` + 断续度联动择时 | 入场支路 | 真新增 | 阈值高到不触发 = 用 earliest |
| STRONG 加断续度调节因子 | `_c_pair_state` | 真新增 | 阈值高到不触发 = 复现 v3 |
| `MAX_GAP_BARS` gap 上限 | `_find_all_pairs` 合并 | 真新增（可选） | `∞` = 复现现状 |
| 不改 | `_schmitt_trigger` / `_fit_physics_parabola` | — | 完全复用，无新数学 |

**新增超参：** `N_confirm`（默认 1=复现）、`gap_count` 阈值（默认高=不触发）、`MAX_GAP_BARS`（默认 ∞）、断续型减仓比例。

### 9.4 零回归先行

所有开关取"复现现状/ v3"值时，系统逐字节复现基线——**回测零回归是第一道验证。** 随后逐条打开（先 N_confirm，再 gap_count 门控，再 effective_start / gap 上限），对比胜率 / 交易次数 / 最大回撤 / Sharpe，**量化每个断续构件的边际贡献**。断续度量化（gap_count/gap_ratio）须最先接入——它是其余三项的输入地基。

## 十、优势与下一步

### 优势

- **断续质量第一次可见。** v1~v3 默认所有半边纯净，从不追问被 0 打断过几次；v4 用 `gap_count/gap_ratio` 把"抖出来的趋势"量化，喂给 C 状态与起点择时。
- **最尖锐的异号 whipsaw 不用新发明。** 只需把 v3 早写好、代码从未落地的 N_confirm 真正接进 `_find_all_pairs`——异号单根被 0 打断、够不到 N_confirm，whipsaw 被自然吞掉。这印证 v3 方向正确。
- **同向真启动点不再丢失。** 断续半边入场择时从"可能是噪声的最早 +1"改到"最近一次 0→+1 重启"，兼顾早入与去噪。
- **C 状态有了记忆。** STRONG 按断续度细分，抖出来的强同向背书打折，不再与干净强趋势同等对待。
- **诚实、可复现。** 明确区分真新增与补落地 v3；所有开关默认复现现状/ v3，零回归先行验证，再逐层量化边际贡献。

### 一处待定（可配置）

断续型 STRONG 的默认响应是"打折/减仓"而非"直接不入"，理由是本级趋势可能仍有效。保守派可能希望断续型一律不入。因此断续阈值与减仓比例设为可配超参，留给回测拍板。

### 下一步（MVP）

```
1. 断续度量化    —— _find_all_pairs 保留 gap 信息，加 gap_count/gap_ratio（地基，最先做）
2. N_confirm 缓冲 —— dir 判定 + 离场① 接入 reverse_run ≥ N_confirm（补落地 v3）
3. 起点重定义    —— effective_start + 断续度联动择时
4. C 断续调节    —— STRONG 细分连续型/断续型，断续型打折
5. gap 上限(可选) —— MAX_GAP_BARS，默认 ∞
6. 零回归验证    —— 全开关复现现状/ v3，再逐层打开量化贡献
```

参数调优聚焦：`N_confirm`（异号缓冲强度 = 核心）、`gap_count/gap_ratio` 阈值（断续型分界）、断续型减仓比例、`MAX_GAP_BARS`（趋势中断线）。先验证关掉全部开关时回测零回归，再逐层打开。
