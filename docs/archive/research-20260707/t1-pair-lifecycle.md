# 多空对（Pair）生命周期、窗口滑动影响与半边 Pair 可靠性分析

> 代码依据：`filter/services/filter_engine.py`
> - `_schmitt_trigger`（行 434-517，状态机 483-514）
> - `_find_all_pairs`（行 520-576）
> - `_compute_strategy_pnl`（行 649-860，Pair 消费逻辑 700-841）

---

## 摘要与一处关键代码事实（必须先厘清）

在展开分析前，必须先纠正一个直觉误区，它贯穿全文：

**`_find_all_pairs` 返回的 `all_pairs` 中，根本不包含"半边 Pair"。**

看 Step 3（行 570-574）：

```python
for j in range(len(merged) - 1):        # 注意：只遍历到倒数第二个
    s1, e1, v1 = merged[j]
    s2, e2, v2 = merged[j + 1]
    if v1 != v2:
        pairs.append((s1, s2))          # pair_end = s2 = 反向段的入口
```

配对循环止于 `len(merged) - 1`，即**每一个 Pair 都必须有一个"下一段反向信号"来收尾**。窗口最右侧那个仍在延伸、尚无反向信号的非零段（也就是任务定义的"半边 Pair"），因为没有 `merged[j+1]`，永远不会被写进 `pairs`。

这一点决定了整个系统的性格：

1. `all_pairs` 里的每个 `(pair_start, pair_end)` 都是**已完成对**：`pair_start=s1` 是本段趋势起点，`pair_end=s2` 是**下一段反向趋势的诞生点（入口边缘）**。
2. `_compute_strategy_pnl` 在 `entry_idx = pair_end`（行 737）入场，方向取 `v2 = sig_t[pair_end]`（行 729）——也就是**在反向趋势诞生的那一刻，顺着反向趋势方向进场**。因此 `pair_end` 对"上一段"是终点，对"下一段"是起点。
3. 由于半边 Pair 不在 `all_pairs` 中，**当前实现事实上就是 Part 3 里的"策略 A（保守，不交易半边 Pair）"**。系统只有等趋势结束、反向信号出现、Pair 完成之后，才会承认并消费它。

记住这条主线，下面 Part 2 / Part 3 的每一个结论都能对上代码。

## Part 1：Pair 的完整生命周期（与状态机对齐）

任务给出的状态机是准确的，这里补充**它为什么成立**——根源在 `_schmitt_trigger` 的状态转移（行 487-513）：

- **进场是"与门"**：`state 0 → +1` 需要 `a > eps AND v > 0`；`→ -1` 需要 `a < -eps AND v < 0`（行 493-498）。加速度和速度必须同时同向，门槛高。
- **离场是"或门 / 单条件"**：`state +1 → 0` 只需 `a < -eps`（行 502），**不检查 v**；`state -1 → 0` 只需 `a > eps`（行 508）。
- **±1 永不直接跳到 ∓1**：多头要变空头，必须先经过 `0`（至少一个观望 bar）。这保证了 `_find_all_pairs` 收集到的非零段之间**总是隔着零**，异号段天然分离。

因此一个 Pair 的诞生（PAIR_BORN）需要"加速度+速度共振"这个较严格的条件，而它的存活（PAIR_ALIVE）只要加速度不强烈反向即可维持——**进场严、持有松**的非对称迟滞（hysteresis），正是趋势段能"长出来"的原因。

Step 2 的合并逻辑（行 559-566）进一步加固了这一点：`+1, 0, +1` 会被合并成一个连续多头段，趋势中间的短暂观望不会把一个 Pair 撕成两个。这是 Pair 相对 Sig 抗噪的结构性来源。

## Part 2：窗口滑动对 Pair 的影响（重点）

前提量化数据（来自根因分析）：SMA 下的边缘区宽度 2-5 bar，边缘区内 Sig 变化概率 5-10%。回测每前进 1 bar，`_schmitt_trigger` 会在新窗口上**重算全部 EWMA 和状态机**。关键在于：重算虽然是全局的，但**只有最右侧边缘区的 bar 的 Sig 有实质翻转可能**，窗口深处的 bar 早已越过死区、状态锁定。下面逐场景对照代码。

### 场景 A：Pair 延长（~70-80%，趋势市）

新 bar 到来后，最右侧非零段的 `sig` 继续同向。对 `_find_all_pairs` 而言，Step 1 收集到的最后一个 segment 的 `end` 右移一位；由于它仍是"半边"（无后续反向段），`all_pairs` **不新增任何完成对**。

**代码含义**：`all_pairs` 列表长度不变，已有完成对的 `(pair_start, pair_end)` **逐字节不变**。策略侧 `_compute_strategy_pnl` 的入场/离场判定完全稳定——延长发生在"尚未被承认"的半边区，对已落账的交易零影响。这是最良性场景。

### 场景 B：Pair 缩短 / 边缘区 Sig 反转（~5-10%）

新窗口下，边缘区内某个原本 `+1` 的 bar 被重算成 `0` 或 `-1`（概率 = 边缘区 Sig 变化概率 5-10%）。

对代码的影响要分两层看：

- **若翻转发生在半边段内部**：只改变最后一个 segment 的 `start/end`，仍不产生完成对，`all_pairs` 不变。
- **若翻转恰好制造出一个反向段**：`merged` 多出一个异号段，Step 3 就会把原本的半边段**收尾成一个完成对**——`all_pairs` 新增一项 `(s1, s2_new)`。

**关键结论（与任务"start 不变"论断一致）**：新完成对的 `pair_start = s1` 取自 `merged[j]` 的起点，而 `s1` 位于窗口深处、早已锁定，**不随窗口滑动改变**。变的只是 `pair_end = s2`（反向入口），且它出现在最右边缘。也就是说：**Pair 的左端（已锁定资产）绝对稳定，只有右端在边缘区抖动**。策略在 `entry_idx = pair_end` 入场，因此不确定性完全集中在"入场时点/方向"这一侧，历史仓位不会被追溯改写。

### 场景 C：Pair 消失 / 被否定（~2-5%，最严重）

需要**边缘区内连续多个 bar 的 Sig 同时归零**，才能让一个刚成形的非零段整体消失。因为要求多个 bar 的联合翻转，概率显著低于单 bar（5-10%）的平方级别，落在 2-5%。

**代码含义**：这只会打击"最右侧尚未完成的半边段"或"上一帧刚刚因场景 B 才诞生、pair_end 紧贴边缘的完成对"。由于 `all_pairs` 里的完成对 `pair_end=s2` 必须由一个反向段支撑，一旦这个反向段被整体抹平，`merged` 里少一个异号段，Step 3 少产出一项——**该完成对从 `all_pairs` 中消失**。

危险点正在于此：如果上一帧策略已经在这个 `pair_end` 入了场（记入 `trade_records`），而这一帧它消失了，就出现了"幽灵交易"——一笔基于已被否定信号的持仓。**这是半边 Pair 中途入场（策略 B）最大的风险敞口**，也是当前实现选择"只认完成对、等 Pair 落地才交易"的深层原因：把入场点从"半边段的诞生"推迟到"下一段反向信号出现"，等于用一整段趋势的确认期，把场景 C 的否定风险挡在门外。

### 场景 D：Pair 分裂 / 合并（~3-8%）

边缘区中间的一个 `0` 变非零、或一个非零变 `0`，直接改变 `_find_all_pairs` 的 Step 2 合并结果：

- `0` 变同向非零：本已被合并的段无变化（Step 2 本就跨零合并），`all_pairs` 稳定。
- 一个非零变 `0`，把 `+1,+1,+1` 断成 `+1,0` 再遇到反向：可能改变某个 segment 的 `end`，但 Step 2 会把同号重新粘合，**净效果通常被合并逻辑吸收**。
- 真正的结构变化发生在：中间冒出一个**异号** bar，把一个长多头段劈成"多—空—多"，Step 3 因此多出一对配对，`all_pairs` 结构改变。

**代码含义**：Step 2 的跨零合并（行 563-564）是一个强力的稳定器，它把"零的抖动"几乎全部消化掉，使场景 D 中"因零变化导致的分裂/合并"绝大多数不落地。真正能改变 `all_pairs` 结构的，只有**异号 bar 的出现**——而异号 bar 要求 `a` 越过相反方向的 `eps` 且（进场时）`v` 同向，门槛远高于单纯归零，这把 D 的有效概率压在低位。

### Part 2 小结

| 场景 | 触发条件 | 对 `all_pairs` 的实际影响 | 已锁定仓位受影响？ |
|------|----------|--------------------------|------------------|
| A 延长 | 半边段同向续 | 无（仍是半边） | 否 |
| B 缩短/反转 | 边缘 1 bar 翻向异号 | 可能新增 1 个完成对，`pair_start` 锁定 | 否（仅右端） |
| C 消失 | 边缘多 bar 同时归零 | 可能删除紧贴边缘的完成对 | **是（幽灵交易风险）** |
| D 分裂/合并 | 边缘冒出异号 bar | 结构变化，多被 Step2 合并吸收 | 少数情况是 |

**贯穿性结论**：`_find_all_pairs` 的 Step 1（连续非零段）+ Step 2（跨零合并）联合作用，使得**任何 Pair 的左端（pair_start，位于窗口深处）都不随窗口滑动而变**，全部不确定性被压缩到最右侧边缘区的 `pair_end` 一侧。这是"Pair 优于 Sig"的结构性根据——噪声只能动右端，动不了已锁定的左端。

## Part 3：半边 Pair 深度分析（重点）

### 3.1 三种命运，与代码严格对应

半边 Pair = 窗口最右侧、`_find_all_pairs` 尚未收尾的那个非零段。它**不在 `all_pairs` 里**，所以在当前实现下**根本不会被交易**。它的三种命运，对应到 `all_pairs` 的未来变化：

| 命运 | 代码表现 | 概率(SMA) | 对 `all_pairs` |
|------|----------|-----------|----------------|
| **成长** | 最后 segment 的 `end` 右移，仍无反向段 | ~70-80% | 不变，仍不被承认 |
| **完成** | 出现反向段 → Step3 收尾为完成对 | ~15-20% | **新增 1 项**，下一帧才会被交易 |
| **消失** | 起点附近 Sig 归零 → segment 蒸发 | ~5-10% | 无新增（幸而未被交易，无损失） |

这张表最重要的信息是：**"消失"命运（假信号）在当前实现下代价为零**——因为半边 Pair 从未入场。系统用"推迟到完成"换取了对假信号的天然免疫。代价是"成长"和"完成"两种命运下，趋势的前半段利润被主动放弃（下面 3.3 详述）。

### 3.2 可靠性指标——哪些能从现有代码直接读出

任务给出的 6 个可靠性指标，可分为"代码已有原料"和"需外部引入"两类，这决定了策略 B（条件入场）落地时的改造成本：

| 指标 | 高可靠 | 代码可得性 |
|------|--------|-----------|
| Pair 已持续时间 | ≥5 bar | **现成**：`_schmitt_trigger` 返回 `dur_t`（行 514），直接是当前段持续期 |
| Pair 内部 Sig 纯度 | 无中间 0 | **可算**：扫 `sig_t[start:end]` 数 0 的个数即得 |
| C 周期同向 Pair | C 已锁定同向 | 需跨周期数据（`_align_pnl_to_current_tf` 一带有跨周期基建，行 867+） |
| v 方向 | 与 Pair 同向且稳 | **现成**：`v` 是 `_schmitt_trigger` 输入；`mu_v` 可判稳定性 |
| 预测曲线方向 | `pred_up` 与 Pair 同向 | **现成**：`_compute_strategy_pnl` 行 726 已算 `pred_up` |
| 起点边缘区状态 | 已离开边缘（锁定） | **可判**：用 `dur_t` 或距边缘距离 `n-1-start` 判断 |

结论：6 个指标里有 4 个（持续时间、纯度、v 方向、pred_up）**当前代码已有全部原料**，实现策略 B 主要是"把 `_compute_strategy_pnl` 的入场点从 `pair_end`（完成对）扩展到当前半边段"并加一道可靠性门。真正需要新建基建的只有"C 周期同向确认"。

### 3.3 三种处理策略，落到本代码上的具体形态

**策略 A（保守，当前实现）**——不交易半边 Pair。
本代码**已经就是策略 A**：`all_pairs` 不含半边，`entry_idx=pair_end` 恒为完成对的反向入口。逻辑代价明确：**当前趋势段的利润被整段放弃**，只有等它完成、下一段反向趋势诞生时，才在 `pair_end` 顺着**下一段**方向入场。换言之系统永远在"交易已确认结束的趋势的下一段"，天然滞后一段。优点是对场景 C（假信号）零暴露。适合回测验证、保守交易者。

**策略 B（条件入场）**——满足可靠性门时，在当前 bar 中途上车。
落地形态：新增一条支路，对最右侧半边段计算 `dur_t ≥ 5`、内部 0 计数为 0、`pred_up` 同向、起点已离边缘（`n-1-start ≥ 边缘宽度`），全部满足才在**当前 bar**（非 5 bar 前的起点）入场，方向 = 半边段方向。
风险敞口：直接暴露于场景 C（~5-10% 概率整段被否定）。因此必须配合止损——恰好 `_compute_strategy_pnl` 的"预测保护期止损"（行 756-771）就是为这种不确定入场设计的：入场后 `[entry+1, entry+n_extend]` 内用抛物线预测轨道做止损，正好覆盖半边 Pair 最可能被否定的窗口。适合实盘、能承担不确定性的交易者。

**策略 C（观察）**——不持仓，但标记，等下一个同向 Pair 加仓。
落地形态：对半边段只记录不下单；待其"完成"（场景变为下一个 `all_pairs` 项）后，若方向被验证正确，在后续同向 Pair 的 `pair_end` 入场时放大仓位。这与当前实现最兼容——只需在现有 `all_pairs` 消费循环里加一个"前一半边段方向是否被确认"的加仓因子。适合追求高胜率的低频交易者。

### 3.4 一个容易被忽略的交互：`pair_end` 的双重身份

再强调一次这个在代码里隐藏、但对半边 Pair 理解至关重要的点：`_compute_strategy_pnl` 里 `entry_idx = pair_end = s2`，方向 `v2 = sig_t[pair_end]` 是**反向段**的方向。所以：

> 一个"半边 Pair 的完成"，在代码里表现为"上一段 Pair 的 pair_end 出现"，而这个 pair_end 同时就是**下一段（新半边）的诞生点和策略入场点**。

半边 Pair 的"完成"和"下一笔交易的开始"是同一个索引 `s2`。这解释了为什么策略 A 虽然放弃了半边段的利润，却不会"错过"——它把交易权推迟到了半边段完成、新趋势诞生的那一刻，用滞后一段趋势换取确定性。理解这个双重身份，才算真正读懂了 Pair 作为策略单元的设计意图。

## Part 4：Pair vs Sig 作为策略单元（代码印证）

任务给出的对比表全部成立，这里只补充"代码在哪里兑现了每一条优势"：

- **稳定性（Pair 起点永不变）**：兑现于 `_find_all_pairs` Step 1+2 —— `pair_start=s1` 取窗口深处已锁定段的起点，见 Part 2 全部四场景的一致结论。
- **交易自然对应**：兑现于 `_compute_strategy_pnl` 行 708 的 `for pair_start, pair_end in all_pairs` —— 一次循环 = 一个 Pair = 一笔交易。
- **噪声敏感性低**：兑现于 Step 2 跨零合并（行 563）—— 单 bar 归零被吸收，动不了 Pair。
- **离场判断内生**：兑现于行 774-781 —— 用反向 `sig_t[i]`（即下一个 Pair 的诞生）作为止盈离场，`Pair.end` 就是自然离场点，无需外部止盈逻辑。
- **半边问题**：兑现于 Step 3 的 `range(len(merged)-1)` —— 半边段被排除在外，系统以"保守策略 A"应对。

**总结论**：Pair 优于 Sig，因为 Pair 把"趋势识别"（Step 1+2 合并成段）与"离场判断"（下一反向段=离场）两件事一次性解决，且把窗口滑动的不确定性从"每个 bar 都可能翻"（Sig）压缩到"只有右端 pair_end 可能变"（Pair）。半边 Pair 是唯一的开放挑战；当前代码用"不交易半边、等完成"这一保守但对假信号免疫的实现（策略 A）来应对，而升级到条件入场（策略 B）所需的可靠性原料，代码已具备大半。
