> **日期**: 2026-07-07
> **状态**: 方案已通过逻辑验证，待实施

---

## 1. 回测过程深度解析

### 1.1 数据流架构

系统采用**四层数据缓存**架构，自下而上依次为：

```
yfinance (互联网) → SQLite (本地DB) → Parquet (按时间窗口切片) → 渲染 (Plotly图表)
```

- **yfinance**: 原始数据源，按需拉取股票OHLCV数据
- **SQLite**: 本地持久化缓存，避免重复网络请求。存储全量历史数据
- **Parquet**: 按回测窗口(默认120个bar)切片存储。每次窗口滑动(`bar_index += 1`)时，`_sync_all_cascading()` 重写所有时间周期的parquet文件
- **渲染**: Streamlit + Plotly 读取parquet数据进行图表绘制

**关键特性**: 粗粒度时间周期(日线/周线/月线)通过**级联合成**从细粒度周期(分钟级)聚合。例如，周线数据从日线聚合而来，而非独立下载。这意味着不完整K线(如周三看到的本周数据)的OHLCV值每帧都在变化。

### 1.2 计算链路

整个信号生成到PnL计算是**严格串行**的流水线：

```
价格序列 → [滤波] → filtered → [np.gradient] → v(速度) → [np.gradient] → a(加速度)
         → [EWMA递归] → sigma_v(波动率) → eps(自适应阈值)
         → [Schmitt状态机] → sig(信号: +1做多/0观望/-1做空)
         → [配对检测] → all_pairs → [抛物线拟合] → pred_pairs
         → [策略PnL计算] → long_pnl, short_pnl, trade_records
         → [跨周期对齐] → 低周期图表上的高周期PnL参考线
```

**核心特点**: 上游任何环节的变化都会级联到下游所有环节。不存在"增量更新"——窗口滑动后整条链路从头重算。

### 1.3 浏览模式 vs 回测模式的关键差异

| 维度 | 浏览模式 | 回测模式 |
|------|---------|---------|
| 数据窗口 | 固定(最近N个bar) | 滑动(模拟时间推进，每次前进1 bar) |
| 数据边界 | 右端始终是"当前时刻" | 右端是回测的"当前时刻点"(过去某个时间) |
| 信号稳定性 | 不关注(只看当前视图) | **核心关注点**(用户会回退对比历史信号) |
| 级联合成 | 最后一bar总是不完整K线 | 每帧的最后一bar都是当年的"不完整K线" |

**浏览模式到回测模式的切换**是发现信号不稳定问题的触发场景。在浏览模式下，用户只看一次性的当前信号；进入回测模式后，每前进一帧信号都可能不同，引发了"我该信哪一个"的困惑。

## 2. 核心问题：Sig/PnL 动态变化根因

### 2.1 因果链全景

滑动窗口前进1个bar(新数据进入，最旧1 bar移出)后，逐层传播的完整链路：

```
[1] 窗口滑动: bar_index += 1
     ↓
[2] 滤波重算: filtered数组变化
     ├── SMA/EMA: 仅最后1-2个点变化 (影响小)
     ├── Savitzky-Golay: 最后~10个点变化 (影响中)
     └── Butterworth(filtfilt): 整个序列全局重算 (影响极大)
     ↓
[3] 速度/加速度: v = gradient(filtered), a = gradient(v)
    边界点使用一阶差分，内部点使用中心差分。filtered影响范围+1~2个点传播
     ↓
[4] ⚠️ 波动率EWMA递归 (放大器1): sigma_v[i] = f(v[0..i]全部历史)
    位置K的v变化 → sigma_v[K:]全部变化。EWMA衰减因子α≈3.3%(span=60)
    例: 1个bar的filtered变化 → 60+个bar的sigma_v变化
     ↓
[5] 自适应阈值: eps = k_eps * max(sigma_v, sigma_min)
    1:1跟随sigma_v变化
     ↓
[6] ⚠️ Schmitt状态机 (放大器2): sig = 三态滞回(+1/0/-1)
    位置K的eps变化 → sig[K]可能翻转 → 从K开始所有后续sig状态重新递推
    例: 1个bar的eps变化 → 可能几十个bar的sig序列完全重建
     ↓
[7] 配对重建: all_pairs从sig数组中提取信号段
    sig序列变了 → 配对列表可能完全重建
     ↓
[8] 拟合重算: 每个pair的抛物线拟合范围变了 → 参数变了 → pred_up可能翻转
     ↓
[9] ⚠️ PnL全局重建: long_pnl和short_pnl从头累积计算
    入场/离场bar变了 → 交易收益变了 → 本金累积路径变了 → 整条曲线面目全非
     ↓
[10] 跨周期对齐: 高周期PnL变了 → 低周期看到的高周期参考线变了
```

**一句话总结**: 1个新bar的数据进入，经过梯度放大、EWMA全局传播、状态机级联后，可能导致整条信号序列和PnL曲线完全重建。这不是单一bug，而是"滑动窗口+自适应信号处理"架构的系统性特性。

### 2.2 量化影响

| 滤波器 | 历史Sig变化概率(每前进1 bar) | 受影响bar数 | PnL曲线变化幅度 |
|--------|---------------------------|------------|----------------|
| SMA/EMA/WMA | 5-10% | 最后1-2 bar | 微小调整 |
| Kalman | 10-20% | 最后~20 bar | 小幅调整 |
| LOWESS | 20-40% | 最后~12 bar | 中等变化 |
| Savitzky-Golay | 30-50% | 最后~10 bar | 中等变化 |
| **Butterworth (filtfilt)** | **~95%** | **全部120 bar** | **面目全非** |

### 2.3 三类根因

#### A类：不可消除的算法固有特性

滑动窗口的数据更替、np.gradient的边界差分退化、滤波器的端点效应、Schmitt触发器的滞回特性——这些都是数学定义决定的，无法消除，只能缓解其影响。

#### B类：可改进的设计选择

| 设计选择 | 当前方案 | 问题 | 替代方案 |
|---------|---------|------|---------|
| 波动率估计 | EWMA递归(全局依赖) | 中间变化传播到末尾 | 滚动窗口标准差(局部依赖) |
| 差分方法 | np.gradient(边界退化) | 边界bar精度不一致 | 统一前向差分 |
| **Butterworth滤波** | **filtfilt(零相位/双向)** | **整个历史每帧重算** | **lfilter(因果/单向)** |
| pair合并 | 0视为同向延续 | 0的插入/移除触发合并/拆分 | 严格配对(0=离场) |

#### C类：实际Bug

1. **哨兵值冲突**: PnL初始值100.0被用作"未持仓"标记。当交易恰好盈亏平衡(PnL=100.0)时，前向填充逻辑错误地将其视为空仓，导致PnL曲线异常
2. **跨周期PnL过期**: session_state中的`_pnl_{tf}`键在无交易帧不更新，导致低周期图表读到过期的高周期PnL数据

## 3. 策略改进渐进方案

### Level 0: 紧急修复 (立即实施，共约20行)

#### L0.1: 哨兵值修复

**修改**: `services/filter_engine.py` 中的 `_compute_strategy_pnl()`

- 将未持仓标记从`100.0`替换为`np.nan`
- 引入独立的`is_holding`布尔遮罩追踪持仓状态
- 前向填充仅对`is_holding=True`的区间生效

#### L0.2: 跨周期PnL过期修复

**修改**: `streamlit_app.py`

- 每个回测帧前进时，清除所有`_pnl_*` session_state键
- 或为每个PnL缓存关联`cutoff_date`，读取时校验是否过期

---

### Level 1: 信号稳定性基础 (核心改进，共约150行)

#### L1.1: 滤波引导与因果默认

**修改**: `components/sidebar.py` + `services/filter_engine.py`

- **默认滤波器改为SMA(period=20)**，替代当前的Butterworth
- 选择Butterworth或LOWESS时显示警告："非因果滤波器——历史信号可能随新数据到达而变化"
- 可选：为Butterworth增加`lfilter`(因果/仅前向)模式，避免零相位双向滤波的历史重写问题

**预期效果**: 历史信号变化概率从~95%降至5-10%，10倍稳定性提升

#### L1.2: 边缘Bar锁定

**修改**: `services/filter_engine.py` (`_schmitt_trigger`) + `components/charts.py`

核心思路：将数据窗口分为"历史区"(稳定)和"边缘区"(不稳定)：

```
[0 ...................................... N-edge_zone] [N-edge_zone ... N-1]
 ← 历史区：Sig已锁定，永不改变 →                ← 边缘区：Sig标记为pending →
```

- 定义边缘区宽度 = `filter_window / 2`(默认10 bar)
- 一旦bar移出边缘区，其Sig值永久锁定
- 边缘区内的Sig标记为`pending`(区别于+1/0/-1)
- 图表上pending信号使用虚线/浅色渲染，明确告知用户"此信号待确认"

**预期效果**: 用户看到的历史信号完全稳定，仅最后2-5 bar可能变化且被明确标注

#### L1.3: 信号确认

**修改**: `services/filter_engine.py` (`_schmitt_trigger`)

- 增加`confirm_bars`参数(默认2)
- Schmitt触发器的原始输出需连续`confirm_bars`个bar保持一致方向，才确认为正式Sig翻转
- 确认期间信号标记为`pending_confirm`

**预期效果**: 减少30-50%由单bar噪声引起的假信号

---

### Level 2: 多周期协同 (规划中，共约130行)

#### L2.1: 高周期门控

**修改**: `services/filter_engine.py` (新方法 `_apply_tf_constraint`) + `streamlit_app.py`

- **严格模式**: 日线Sig=+1时，60分钟线的做空信号强制置0(顺势交易)
- **宽松模式**: 日线Sig=+1时，60分钟线的做空仓位减半(而非完全禁止)
- 作为后处理步骤，不修改滤波管线本身

#### L2.2: 对齐度评分

**修改**: `services/filter_engine.py`

- 对每个交易信号，计算更高时间周期中有多少比例与当前方向一致
- 评分0.0-1.0，显示在交易信号旁
- 复用现有的`_compute_holding_masks`基础设施

---

### Level 3: 动态风险管理 (规划中)

- **L3.1**: ATR动态止损(基于14周期ATR，与现有预测止损取较宽者)
- **L3.2**: 信号稳定性仓位管理(确认bar数和对齐度评分越高，仓位越大)
- **L3.3**: 分批入场/离场(减少滑点和噪声敏感度)

### Level 4: 回测验证框架 (规划中)

- **L4.1**: 绩效面板(Sharpe、Calmar、最大回撤、胜率、盈亏比)
- **L4.2**: 训练/测试分割(前70%优化参数，后30%验证)
- **L4.3**: 参数敏感性热力图(展示各参数对PnL的影响面)

## 5. 关键设计原则

### 5.1 信号与交易分离

策略改进方案遵循"信号生成"与"交易执行"分离原则：
- **Level 1** 解决信号生成的质量问题(信号是否稳定可信)
- **Level 2-3** 解决交易执行的质量问题(何时入场、仓位多大、何时止损)

这样分层的好处：信号稳定性是交易决策的前提。在信号本身还在闪烁时讨论止损和仓位管理是本末倒置。

### 5.2 可回退(A/B对比)

所有Level 1-2的改进都设计为**可配置开关**，而非硬编码替换：
- L1.1: 默认滤波器可切换，用户可手动选回Butterworth
- L1.2: 边缘锁定可通过参数关闭(设置edge_zone=0)
- L1.3: confirm_bars可设为0恢复即时信号
- L2.1: 三种模式(关闭/严格/宽松)

这确保了用户可以A/B对比新旧行为，渐进采纳。

### 5.3 大方向优先

MVP选择了"最大收益/最小改动"的方案组合：
- L1.1(改默认值+加警告)是单一最大杠杆改动——10倍稳定性提升仅需30行代码
- L0.1+L0.2是无需争议的纯bug修复——不应该在脏数据上做任何分析
- L1.2是用户体验的质变——从"信号神秘消失"到"pending区透明标注"

### 5.4 渐进式叠加

设计保证了方案可以"用一点、加一点"，不需要一次性全部实施：
- 仅L0即可消除两个已知bug
- L0+L1.1即可获得10倍稳定性提升
- 加上L1.2即可获得完整的信号稳定性
- 后续Level可选叠加，互不阻塞

### B. 术语表

| 术语 | 含义 |
|------|------|
| **Bar** | 一根K线，代表一个时间单位的OHLCV数据 |
| **Filtered** | 滤波后的价格序列(如SMA平滑线) |
| **v / a** | 速度/加速度：filtered的一阶/二阶数值导数 |
| **sigma_v** | v的EWMA波动率估计 |
| **eps** | 自适应阈值：k_eps * max(sigma_v, sigma_min) |
| **Sig** | 信号：+1做多 / 0观望 / -1做空，由Schmitt触发器产生 |
| **Schmitt触发器** | 带磁滞(hysteresis)的三态状态机，防止阈值附近反复跳变 |
| **Pair** | 一个做多或做空信号段，从同方向信号开始到反方向信号出现结束 |
| **因果/非因果滤波** | 因果=仅使用过去数据(如SMA/EMA)；非因果=使用未来数据(如filtfilt双向滤波) |
| **级联合成** | 从细粒度周期聚合出粗粒度周期的OHLCV(如分钟→日线→周线) |
| **Pending** | 边缘区内的信号状态标记，表示"此信号尚未稳定，可能随新数据到达而变化" |
| **边缘区(Edge Zone)** | 数据窗口最右端N个bar，滤波器的端点效应在此区域内最明显 |
