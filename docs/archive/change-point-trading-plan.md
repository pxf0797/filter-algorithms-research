# 周期变化点监测与交易方案

> 基于 2026-07-07 深度研究 -- 五层变化点体系 + 六种策略模式

---

## 一、什么是"变化点"

通俗地说，**变化点就是系统中某个状态发生改变的时刻**。它不是一个抽象概念，而是可观测、可追踪、可交易的具体事件。在我们的系统中，处理链是这样的：

```
价格序列 → 滤波(filtered) → 速度 v → 加速度 a → 波动率 sigma_v
    → 自适应阈值 eps → 施密特信号 sig → 配对段 pairs → 拟合预测 → PnL
```

在这条链上，每一个环节都可能产生变化点。例如：

- **加速度 a 突破阈值 eps** -- "市场开始加速了"
- **速度 v 从负变正** -- "价格运行方向在改变"
- **Sig 从观望变做多** -- "系统发出了做多信号"
- **滤波价格触及局部谷底** -- "价格可能见底了"
- **波动率 sigma_v 突然放大** -- "市场进入高不确定状态"

这些变化点分布在不同的处理层上，从快到慢、从不稳定到稳定排列：

```
早 ─────────────────────────────── 时间 ──────────────────────────────→ 晚

Layer A (触发层)     Layer B (信号层)    Layer C (滤波层)    Layer D (配对层)
┌──────────┐      ┌──────────┐     ┌──────────┐      ┌──────────┐
│ v穿越0   │      │ Sig翻转  │     │ filt极值 │      │ pair边界 │
│ a穿越eps │  →   │ 0→±1    │ →   │ 交叉确认 │  →   │ 起止确认 │  →  锁定
│ sigma_v  │      │ ±1→0    │     │ 斜率突变 │      │ pred_up  │
└──────────┘      └──────────┘     └──────────┘      └──────────┘
 最早/最不稳定      较稳定/可靠       天然滞后          最可靠/最滞后
```

完整的五层体系及每层含义如下表：

| 层级 | 名称 | 典型变化点 | 特点 | 适合做什么 |
|------|------|-----------|------|-----------|
| Layer A | 触发层 | a穿越eps、v穿越0、sigma_v突变 | 最早感知变化，但假信号率高 | 预警，不是入场依据 |
| Layer B | 信号层 | Sig 0→+1（做多）、Sig +1→0（平多） | 滞回确认，过滤了噪声 | 核心入场/离场信号 |
| Layer C | 滤波层 | filtered局部极值、filtered/noisy交叉 | 天然滞后但有几何直观性 | 支撑/阻力位标记 |
| Layer D | 配对层 | pair_start、pair_end、pred_up翻转 | 离实际交易最近，但上游变化的汇聚点 | 趋势确认、复盘分析 |
| Layer E | 跨周期层 | 高周期Sig翻转、跨周期时间差 | 大方向约束 | 判断"能不能做"，而非"什么时候做" |

**关键理解**：变化点不是一成不变的。因为滤波器的端点效应，窗口最右侧的 bar 上的变化点会在新数据加入后发生变化甚至消失。但一旦某个 bar 离开了"边缘效应区"，该 bar 上的所有变化点就**永久锁定**了。

## 二、核心矛盾：稳定性 vs 时效性

这是所有基于变化点的交易策略面临的根本权衡。

### 2.1 边缘区的概念

每次回测窗口滑动（新数据加入），窗口最右侧的一小段 bar 上的数值会发生变化。这一段就是**边缘区**。不同滤波器的边缘区宽度如下：

| 滤波器 | 边缘区宽度 (bar) | 特点 |
|--------|-----------------|------|
| SMA / EMA / WMA | 2-5 | 最稳定，边缘区窄，推荐用于回测 |
| Kalman | 5-15 | 状态估计需要收敛 |
| LOWESS | 8-15 | 局部加权回归边界非对称 |
| Savitzky-Golay | 8-12 | 多项式拟合边界不稳定 |
| Butterworth | **全窗口** | 零相位滤波全局重算，**不建议用于回测** |

### 2.2 稳定性与时效性的张力

想象一条连续光谱：

```
              稳定性低/时效性高              稳定性高/时效性低
              ←───────────────────────────────────────────→

              a穿越eps    v穿越0   Sig翻转   filt极值   pair_start   pair_end
              触发层      触发层    信号层    滤波层     配对层       配对层
              
消失率(边缘区内): 30-50%    15-30%    5-10%     <5%        <5%         <3%
入场延迟:        0-1 bar   1-2 bar  2-4 bar  3-5 bar   4-6 bar     >6 bar
```

**越早的变化点**（如触发层的 a 穿越 eps）：
- 优点：及时，能捕捉到趋势的萌芽阶段
- 缺点：30-50% 会在窗口滑动后消失 -- 可能只是噪声

**越晚的变化点**（如配对层的 pair_end）：
- 优点：可靠，消失率低于 3%
- 缺点：已经错过了一大段利润，pair_end 需要反向信号出现才确认

### 2.3 关键量化数据（来自根因分析）

这些数字是整个方案设计的基础：

- **SMA/EMA 下边缘区宽度**：2-5 bar。这意味着大约 2-5 个 bar 后，信号就彻底稳定了。
- **触发层变化点在边缘区内的消失率**：30-50%。每三次预警中，至少有一次是假信号。
- **信号层变化点在边缘区内的消失率**：5-10%。Schmitt 滞回机制大幅过滤了噪声。
- **EWMA sigma_v 的全局依赖**：1 个 bar 的 v 变化可影响 60+ 个 bar 的 eps，再通过 Schmitt 状态机 Cascade 传播到序列末尾。
- **Butterworth 零相位滤波**：边缘区 = 全窗口，历史信号完全不可信。在本方案的所有策略中，Butterworth 被标记为"不适合回测"。

### 2.4 方案设计的核心原则

基于以上认知，所有交易方案必须遵循两条铁律：

1. **不交易边缘区信号**：窗口最右侧 `edge_width` 个 bar 内的变化点不作为入场依据
2. **入场理由消失则离场**：如果某笔交易基于的变化点在后续窗口中消失了，该笔交易的逻辑基础不复存在，应立即离场

## 三、推荐交易方案（从简单到复杂）

### 方案 A：稳定信号跟踪（最简单，MVP 首选）

> **一句话**：等信号稳定了再交易，宁可错过，不愿做错。

**使用的变化点**：Sig 翻转（信号层 B1/B3）+ 边缘区锁定

**入场条件**：
- 历史区（bar_index < 当前窗口末尾 - edge_width）出现 Sig 0→+1 翻转
- 该 bar 已离开边缘区，信号已"永久锁定"
- 做空方向对称：Sig 0→-1 翻转

**离场条件**（三选一）：
- Sig 反向翻转（做多时 Sig→-1 或 0，做空时 Sig→+1 或 0）
- 固定持仓 N bar 后离场
- 价格触发止盈/止损

**止损逻辑**：入场 bar 的极点。做多取入场 bar 的最低价，做空取入场 bar 的最高价。含义："如果价格跌破了当初入场判断的基准，说明判断错了"。

**预期效果**：
- 胜率中等偏高（信号层的 Sig 翻转综合评分 A 级，3.75/5）
- 交易频率中等（只在趋势确认后入场，过滤了盘整市的反复翻转）
- 适合趋势跟踪策略

**数学直觉 -- "用延迟代价换信号确定性"**：

定义：
- `P_flip` = 边缘区内信号翻转消失的概率（信号层约 5-10%）
- `gain_trend` = 趋势延续的预期收益
- `delay_cost` = 等待锁定期间错过的收益

```
立即入场的期望收益：E_immediate = (1 - P_flip) × gain_trend + P_flip × (-cost_flip)
延迟入场的期望收益：E_delayed  = (1 - P_flip) × (gain_trend - delay_cost)

延迟值得当且仅当：P_flip × (gain_trend + delay_cost) > delay_cost
```

在 SMA/EMA 下 `edge_width` 只有 2-5 bar，`delay_cost` 很小；而 `P_flip` 在盘整市中可能高达 20%+，延迟的价值就非常明显。在趋势市中 `P_flip` 低，延迟的代价也很小。因此，**方案 A 在绝大多数市场状态下都是正期望的**。

**优缺点**：

| 优点 | 缺点 |
|------|------|
| 信号确定性强，入场后不会出现"信号闪烁" | 延迟入场，强趋势中错过早期 2-5 bar 利润 |
| 实现仅需 `edge_width` 一个额外参数，约 100 行代码 | SMA/EMA 下延迟可接受，Savitzky-Golay 下延迟较大（8-12 bar） |
| 止损逻辑天然自洽 -- 入场 bar 极点是自然的"判断错误"标志 | Butterworth 完全不可用（边缘区=全窗口） |
| 天然避免"信号闪烁导致错误入场" | -- |

### 方案 C：变化点消失即止损（核心防御机制）

> **一句话**：入场理由没了，留在这里干什么？

**核心思想**：这是对"信号边缘不稳定"最直接的应对。每笔交易都绑定到一个具体的变化点（如 "bar=100 处 Sig 从 0→+1"）。每次窗口滑动后，检查这个变化点是否仍然存在。如果消失了，说明市场否定了当初的入场理由，应立即离场。

**使用的变化点**：追踪入场变化点的跨帧状态

**入场所需变化点**：可以是任何方案中的变化点（方案 A 的 Sig 翻转、方案 B 的预警确认等）

**监控逻辑**：
1. 入场时记录：变化点 ID（`CP_{frame}_{bar}_{direction}`）、对应 bar index、方向
2. 每次窗口滑动（新帧产生）后，检查该 bar 是否已离开边缘区
3. 如已离开边缘区，检查该 bar 上的变化点是否仍然存在（Sig 值是否保持）
4. 如变化点消失 → 立即离场

**关键区分 -- "消失" vs "被覆盖"**：

| 情况 | 表现 | 含义 | 操作 |
|------|------|------|------|
| **消失** | 原始翻转位置的 Sig 值变回 0 | 入场理由被市场否定 | 立即离场 |
| **被覆盖** | 原始翻转仍存在，但附近出现新翻转，pair 边界移动 | 趋势在加速，不是消失 | 继续持有，更新止损到新变化点 |

**预期效果**：
- 大幅减少"信号闪烁导致的持仓" -- 这是最致命的隐性亏损来源
- 止损触发是"逻辑驱动"而非"价格驱动"，避免了噪音止损
- 可能增加交易频率（变化点频繁出现消失的市场中），但每次止损的损失很小

**必要性论证**：

考虑一个典型场景：Sig 在 bar=50 翻转为 +1（做多），入场做多。3 个 bar 后窗口滑动，bar=50 的 Sig 变回 0。如果不使用方案 C，持仓仍然存在但已经失去了逻辑基础 -- 你持有的是一个"信号已消失"的仓位。这种仓位在市场反转时会造成超出预期的亏损。

方案 C 的止损不是价格止损，而是**逻辑止损**。它的触发条件不是"价格跌了多少"，而是"当初让我入场的理由还在不在"。这是一个更本质的风险控制方式。

**优缺点**：

| 优点 | 缺点 |
|------|------|
| 逻辑自洽：入场理由消失 = 离场，不存在"持有无理由仓位" | 需要跨帧追踪变化点，实现复杂度中等（约 80 行） |
| 系统性防御"信号闪烁导致错误持仓" | 需区分"消失"和"被覆盖"，后者需额外合并逻辑 |
| 可与任何其他方案叠加，作为"保底离场"层 | 盘整市中可能频繁开平，但与方案 E（密度过滤）配合可解决 |
| 止损触发是逻辑驱动而非价格驱动 | 变化点追踪器需要跨请求持久化状态 |

### 方案 B：预判 + 确认两步走

> **一句话**：看到苗头就准备，确认信号就动手。

**核心思想**：方案 A 的延迟入场在趋势市中可能错过宝贵的早期利润。方案 B 利用触发层（Layer A）的变化点做预警，信号层（Layer B）的变化点做确认，两步走提前入场时机。

**使用的变化点**：a 穿越 eps（触发层 A1/A2，预警）→ Sig 翻转（信号层 B1/B3，确认）

**两步流程**：

```
第一步（预警）：
  a 穿越 +eps 且 v > 0 → 进入"做多预警"状态
  a 穿越 -eps 且 v < 0 → 进入"做空预警"状态

第二步（确认）：
  预警区内 Sig 翻转 → 入场

取消预警（三种情况）：
  1. a 回到 eps 以内 → 预警取消（假突破）
  2. 预警超时（超过 MAX_WARNING_BARS 仍未确认）→ 取消
  3. v 方向反转 → 取消
```

**预期效果**：
- 相比方案 A 提前 1-3 bar 入场
- 假预警率 20-30%（触发层的先天不稳定，但预警不持仓所以不造成实际损失）
- 需要修改 `_schmitt_trigger` 使其输出内部触发状态（约 60 行额外改动）

**适用场景**：
- 趋势启动初期（a 放大、v 即将跟上时特别有效）
- 不愿等待方案 A 的锁定延迟，愿意接受一定假预警代价的交易者

**优缺点**：

| 优点 | 缺点 |
|------|------|
| 相比纯等待锁定（方案 A），能提前 1-3 bar 入场 | 需修改 Schmitt 触发器输出内部状态 |
| 预警取消机制天然过滤假突破 | 盘整市中预警→取消反复触发（与方案 E 配合可缓解） |
| 利用了"a 先动、Sig 后动"的物理直觉 | MAX_WARNING_BARS 参数需校准 |

### 方案 D：多周期共振

> **一句话**：大家都说涨，那才是真的涨。

**核心思想**：当日线和 60 分钟线的变化点在时间上接近时，形成"共振"，信号可靠性远高于单一周期。

**使用的变化点**：多个周期的 Sig 翻转（Layer E）

**共振强度公式**：

```
共振强度 = Σ( 1 / (1 + |Δtᵢ|) ) × w(tf)

其中：
  Δtᵢ = 周期 i 的变化点与参考周期变化点的时间差
  w(tf) = 周期权重 (建议：日线=1.0, 60min=0.7, 15min=0.4, 5min=0.2)
```

**时间窗口**（"接近"的标准）：

| 参考周期 | 60min ± | 15min ± | 5min ± |
|---------|---------|---------|--------|
| 日线 | ±4 bar | ±16 bar | ±48 bar |
| 60min | -- | ±4 bar | ±12 bar |

**入场条件**：≥2 个周期的 Sig 翻转在同一方向、且在时间窗口内接近，且共振强度超过阈值（如 0.5）。

**预期效果**：
- 交易机会少但质量高，假信号率极低
- 适合大仓位（单笔交易信心高）
- 可与现有跨周期对齐逻辑复用

---

### 方案 E：变化点密度过滤（辅助方案）

> **一句话**：盘整市不交易，等趋势明确了再说。

**核心思想**：变化点的出现频率反映了市场状态 -- 盘整市变化点频繁出现又消失，趋势市变化点稳定保持。通过监控变化点密度（锁定区内的 Sig 翻转频率），判断当前是否适合交易。

**密度度量**：

```
CP_density(t) = 锁定区内 Sig 翻转次数 / 观察窗口 M

状态分类：
  高密度 (>70分位) → 盘整市 → 暂停交易
  正常密度 (30-70分位) → 正常交易
  低密度 (<30分位) → 趋势市 → 正常交易，可适当加重仓位
```

这个方案不直接产生交易信号，而是作为**过滤器叠加到任何方案上**，非侵入式设计。实现简单，仅需统计翻转次数。

### 策略组合建议

将五个方案按以下流程组合，实现渐进式信号确认：

```
                        ┌─────────────┐
                        │  方案 E：    │
                        │  密度过滤    │
                        └──────┬──────┘
                               │
                   盘整市？    │    趋势市/正常
                  ┌────────────┴────────────┐
                  │                         │
              不交易                   ┌────┴────┐
                                      │ 方案 D： │
                                      │ 多周期共振│
                                      └────┬────┘
                                           │
                              有共振？    │    无共振
                          ┌────────────────┴────────────┐
                          │                             │
                    ┌─────┴─────┐                 ┌─────┴─────┐
                    │ 方案 A：   │                 │ 方案 B：   │
                    │ 稳定信号   │                 │ 预判+确认  │
                    │ 跟踪入场   │                 │ 两步入场   │
                    └─────┬─────┘                 └─────┬─────┘
                          │                             │
                          └──────────┬──────────────────┘
                                     │
                              ┌──────┴──────┐
                              │  方案 C：    │
                              │  消失止损    │
                              │  (全过程监控) │
                              └─────────────┘
```

**流程说明**：
1. **先看市场状态**（方案 E）→ 盘整市直接不交易，避免假信号连续止损
2. **再看共振情况**（方案 D）→ 有共振（多周期一致性高）则用方案 A 入场（更稳妥）
3. **无共振则用方案 B**（需要更确信的信号，在盘整市已被 E 过滤的前提下）
4. **所有持仓用方案 C 监控**（入场理由消失则止损，全场生效）

## 四、实施路线图

| 阶段 | 内容 | 改动量 | 预期效果 |
|------|------|--------|---------|
| **第一步** | 方案 A + 边缘区锁定 | ~100 行 | 信号可信度显著提升，消除"交易未锁定信号"的问题 |
| **第一步（并行）** | 方案 E（密度过滤） | ~50 行 | 盘整市不交易，避免连续假信号止损 |
| **第二步** | 方案 C（消失止损） | ~80 行 | 系统性防御信号闪烁，避免"持有无理由仓位" |
| **第三步** | 方案 B（预判确认） | ~60 行 | 在趋势市中提前 1-3 bar 入场 |
| **第四步** | 方案 D（多周期共振） | ~150 行 | 高确信度交易，适合大仓位部署 |

**第一步是 MVP**：方案 A + 方案 E 的组合即可构成完整的最小可用版本。方案 A 保证入场信号可靠，方案 E 保证不在错误的市况下交易。两者叠加，总共约 150 行改动，预期可消除当前系统中 80% 以上的"信号闪烁导致的错误交易"。

**第二步是关键防御**：方案 C 的消失止损是方案 A 的天然搭档。方案 A 保证了入场的可靠性，方案 C 保证了持仓期间逻辑的持续有效。两者配合，形成"入场确认 + 持仓监控"的完整闭环。

**第三和第四步是性能提升**：在基础架构稳定后，方案 B 提升入场时效性，方案 D 提升信号质量。两者依赖前两步建立的变化点追踪基础设施。

## 五、关键设计决策

### 5.1 变化点追踪器（ChangePointTracker）

这是方案 C/D/E 的核心基础设施 -- 一个独立的数据结构，跨帧追踪每个变化点的生命周期：

```
ChangePoint {
    id: "CP_{frame}_{bar}_{direction}"   -- 唯一标识
    bar_index: int                        -- 变化点所在的 bar 位置
    direction: +1 | -1                    -- 方向
    first_seen_frame: int                 -- 首次出现的帧号
    last_seen_frame: int                  -- 最后确认存在的帧号
    status: pending | active | vanished | covered
    lock_frame: int | null                -- 离开边缘区的帧号（锁定帧）
}
```

追踪器每次窗口滑动后执行：
1. 检查所有 `pending` 变化点是否已离开边缘区（→ 转为 `active`）
2. 检查所有 `active` 变化点是否仍在锁定区中存在（→ 不存在则转为 `vanished`）
3. 区分 `vanished`（真正消失）和 `covered`（被新变化点覆盖）

**注意事项**：追踪器在窗口大幅滑动（如跳 bar）时的行为需特别处理。如果窗口滑动幅度超过 `edge_width`，可能出现多帧之间的变化点索引不对齐。建议在跨越帧时通过时间戳而非 bar index 来匹配变化点位置。

### 5.2 策略可组合性

每个方案设计为独立的"策略模块"，输入输出接口统一：

```python
class StrategyModule:
    def on_new_frame(self, frame_id, sig_sequence, price_data, ...) -> list[TradeSignal]:
        """每帧调用，返回该帧的交易信号"""
        pass

    def on_trade_closed(self, trade: Trade) -> None:
        """交易关闭回调，用于状态更新"""
        pass
```

模块之间不直接依赖，通过变化点追踪器共享状态。这样新的方案可以像插件一样加入或移除。

### 5.3 与现有系统的集成

本方案设计时充分考虑了复用现有组件：

| 现有组件 | 如何使用 |
|---------|---------|
| `_schmitt_trigger` | 方案 A 直接使用其输出的 Sig 序列；方案 B 需扩展其输出内部触发状态 |
| 边缘区锁定逻辑 | 所有方案共用 `edge_width` 参数；可通过 filter 类型自动查表获取 |
| `_compute_strategy_pnl` | 所有方案生成的交易信号最终通过此函数计算 PnL |
| `_find_all_pairs` | 方案 C 中区分"消失"和"被覆盖"时需要检查 pair 边界的移动 |
| 跨周期对齐 `_align_pnl_to_current_tf` | 方案 D 中复用时间对齐逻辑 |

## 六、风险与注意事项

### 6.1 变化点追踪器在窗口大幅滑动时的行为

当回测窗口不是逐 bar 滑动而是跳 bar（如从 bar 1-120 跳到 bar 30-150）时，变化点追踪器可能遇到 bar index 不对齐的问题。建议：
- 通过时间戳（而非 bar index）匹配跨帧变化点
- 在窗口跳跃超过 edge_width 时，清空 pending 状态的变化点（它们在边缘区内的历史已不可追溯）

### 6.2 不同滤波算法下边缘区宽度不同

这是本方案最重要的参数依赖。`edge_width` 必须在策略初始化时根据滤波器和窗口大小自动确定：

| 滤波器 | edge_width (bar) | 策略参数调整 |
|--------|-----------------|-------------|
| SMA/EMA/WMA | 2-5 | 默认参数，所有方案直接可用 |
| Kalman | 5-15 | 方案 A 延迟增大，推荐切换到方案 B + C |
| Savitzky-Golay | 8-12 | 方案 A 延迟不可接受，必须用方案 B；方案 D 的共振更关键 |
| Butterworth | 全窗口 | **所有方案失效**，标记为"不适合回测" |

### 6.3 避免过拟合

这是方案设计中刻意强调的原则：**方案参数应基于逻辑而非历史回测优化**。

- `edge_width` 来自于滤波器的数学性质，不是调出来的
- 方案 B 的 `MAX_WARNING_BARS` 应该基于"a 穿越到 Sig 翻转的平均间隔"而非回测最优值
- 方案 D 的周期权重 `w(tf)` 应该基于时间周期的信息密度比例，而非历史胜率拟合
- 方案 E 的分位数阈值应该使用长历史滚动计算，而非单段回测最佳值

### 6.4 Butterworth 的处理

Butterworth 零相位滤波的边缘区覆盖全窗口，导致所有基于变化点锁定状态的策略模式失效。这在当前系统中是一个硬限制。建议：**在回测引擎中对 Butterworth 滤波类型添加告警**，或直接限制其仅用于可视化/分析场景，不参与交易信号生成。

### 6.5 EWMA sigma_v 的全局依赖残留影响

即使使用锁定区内的变化点（方案 A），EWMA sigma_v 的全局依赖仍然存在 -- 因为它影响 eps，而 eps 影响所有 Sig 的位置。虽然锁定区内的 Sig 值本身不再变化，但锁定的 bar 和未锁定的 bar 之间的 sig 序列可能因 eps 变化而出现新的翻转位置。建议：在 sigma_v 的 EWMA 衰减窗（span=60）刚刚滑过旧数据时，额外增加 1-2 bar 的安全边际。

## 七、方案选择速查表

根据你的交易风格和系统配置，选择最适合的起点：

| 你的情况 | 推荐起点 | 理由 |
|---------|---------|------|
| 刚接触、希望最小改动先跑起来 | **方案 A** | 100 行改动，SMA/EMA 下立即可用 |
| 被"信号闪烁导致错误持仓"困扰 | **方案 A + C** | 入场确认 + 消失止损 = 完整闭环 |
| 使用 Savitzky-Golay 或 Kalman 滤波 | **方案 B + C + E** | 大边缘区下方案 A 延迟过大 |
| 追求高质量大仓位交易 | **方案 A + C + D + E** | 多周期共振仅在高确信度下入场 |
| 已有 Butterworth 策略想复用 | **不建议** | Butterworth 下所有锁定检测失效，请切换到 SMA/EMA |

## 附录：与前期根因分析的关联

| 前期发现 | 本方案的应对 |
|---------|------------|
| **滤波器端点效应**（SMA/EMA 2-5 bar, Butterworth 全窗口） | 方案 A 只交易锁定区；方案 E 只统计锁定区密度；Butterworth 标记为不适合回测 |
| **EWMA sigma_v 全局依赖**（1 bar v 变化 → 60+ bar eps 变化） | 方案 E 密度升高是 sigma_v 全局变化的"症状"信号；方案 C 追踪变化点状态而非依赖 sigma_v 值 |
| **Schmitt 状态机 Cascade**（上游 eps 变化 → sig 序列后向传播） | 方案 A 延迟入场直到信号稳定；方案 C 信号消失则离场；方案 E 高密度 = Cascade 频发 → 暂停 |
| **Butterworth filtfilt 全局重算** | 所有方案均无法在 Butterworth 下工作（无锁定区），强烈建议限制其仅用于分析/可视化 |
| **哨兵值 100.0 bug** | 方案 C 追踪变化点状态而非 PnL 值，绕过此 bug |
| **pair 合并逻辑导致边界移动** | 方案 C 区分"消失"和"被覆盖"，后者是 pair 合并导致而非真正消失 |
| **跨周期 PnL 不写入** | 方案 D 依赖可靠的跨周期数据，该 bug 修复是前提 |
