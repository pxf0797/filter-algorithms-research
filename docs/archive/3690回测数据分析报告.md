```

  │
  └─ return results          ← list[dict]，每个元素是一个 bar 的完整管道状态

ParquetStore.append_row()
  │
  ├─ _extract_row() → _extract_view_columns()
  │    ├─ sig, filtered, eps → 取数组[-1]
  │    ├─ long_pnl, short_pnl → 取数组[-1]
```

**关键数据流要点：**

- BacktestRunner 产出的每个 `stage_output` 包含**完整窗口**的数组（长度=n_pts 或接近n_pts）
- ParquetStore 从这些数组中只提取**最后一个元素**（`[-1]`）存入 parquet
- BS marker 和 trade 的匹配使用 `<= view_last_idx` 而非精确 `==`（原因见 2.4）

## 2. 核心概念

### 2.1 min_tf 与统一时间轴

**min_tf** 是视图中**最高频（最精细）周期的统一时钟**。在本次回测中：

- v0=15分钟、v1=60分钟、v2=日线、v3=周线
- **min_tf = 15分钟**（ALL_TFS 中索引最小）
- 回测循环按 15 分钟 bar 为步长推进：`for bar_index in range(300, 800, 1)`
- 每一步的 `cutoff_date` 取 min_tf 对应 bar 的 ts 字段

```
bar_index:  300    301    302    303    ...    799
            |      |      |      |             |
15min bar:  B300   B301   B302   B303  ...    B799
60min bar:  [---- B60_1 ----]   [---- B60_2 ----]
日线 bar:   [----------- 4月20日 ----------]
```

每步循环中，所有 4 个视图都重新计算——虽然高周期数据在同一步内可能完全相同（因为高周期的 bar 变化缓慢），但管道仍然完整运行。

### 2.2 窗口计算与 [-1] 取值

这是理解回测存储最关键的概念。

`_compute_pipeline_for_view()` 计算以下数组：

| 数组 | 典型长度 | 含义 |
|------|---------|------|
| `t` | n_pts（15分钟=50, 60分钟/日线=60, 周线=60） | 窗口内 bar 索引 0, 1, 2, ... |
| `filtered` | 同 t | 滤波器输出价格序列 |
| `schmitt["sig"]` | 同 t | 信号：+1做多, -1做空, 0中性 |
| `schmitt["eps"]` | 同 t | 噪声水平估计 |
| `long_pnl` | 同 t | 做多策略累计净值（起始=100） |
| `short_pnl` | 同 t | 做空策略累计净值 |

**数组坐标系：窗口内部索引 0..n_pts-1，不是全局 bar_index。**

例如：在 bar_index=450 时：
- v0（15分钟，n_pts=50）：窗口内索引 0~49，对应全局 bar_index 401~450
- v2（日线，n_pts=60）：窗口内索引 0~59，对应过去 60 个交易日

**`[-1]` 代表什么？**

`[-1]` = 数组最后一个元素 = 窗口内**最新时刻**的状态 = **当前 cutoff_date 时刻**的状态。

- `schmitt["sig"][-1]` = 当前时刻的信号方向
- `long_pnl[-1]` = 从起始到当前时刻的累计净值（如 104.56 表示 +4.56%）
- `filtered[-1]` = 当前时刻的滤波价格

### 2.3 全局 bar_index vs 视图窗口索引

| 概念 | 说明 |
|------|------|
| **全局 bar_index** | min_tf 上的绝对位置（300~799），parquet 中 `bar_index` 列 |
| **视图窗口索引** | 各视图 `t` 数组的内部索引（0, 1, 2, ..., n_pts-1），用于管道内部计算 |
| **view_last_idx** | `len(t) - 1`，即窗口最后一个元素的内部索引 |

**为什么日线视图和 15 分钟视图的 bar 数量一样？**

parquet 文件的每行对应一个 15 分钟 bar（min_tf 步长）。日线视图的那行数据只是该 15 分钟时刻的日线窗口快照——日线 bar 跨越多行 15 分钟 bar。所以 parquet 中：

- 500 行 = 500 个 15 分钟 bar
- v2（日线）v2_sig 也有 500 个值，但其中相邻行的值往往相同（因为日线 bar 没变）
- 日线信号变化频率远低于 15 分钟信号，因为日线 bar 约每 23 个 15 分钟 bar 才更新一次

### 2.4 BS marker 和 trade 的 `<=` 匹配逻辑

这是代码中一个精心设计的细节。

```python
view_last_idx: int = len(t_arr) - 1 if t_arr is not None else -1

# BS markers:
for m in bs_markers.get("entry_markers", []):
    if int(m[0]) <= view_last_idx:   # ← 注意：<= 不是 ==
        bs_entry = str(m[1])
```

**为什么必须用 `<=` 而非 `==`？**

BS marker 的 `bar_idx`（`m[0]`）是**视图窗口内索引**。entry marker 的 `bar_idx` = `pair_end`（施密特触发器的多空切换点）。这个 `pair_end` **几乎不可能恰好等于** `view_last_idx`（窗口的最后一个索引）。

举例：
- 如果 entry 发生在窗口内索引 45，而 `view_last_idx` = 49
- 用 `==` 比较：45 != 49 → 不匹配，bs_entry 为空 → **漏掉已经发生的入场信号**
- 用 `<=` 比较：45 <= 49 → 匹配，bs_entry 正确记录 "B" → **正确**

同理，trade 的 `exit_idx` 和 `entry_idx` 也是如此——交易事件发生在窗口内某个位置，只要它已经发生（`<= view_last_idx`），就应该被记录。

**这意味着：** parquet 中 BS marker 列存的是"到当前时刻为止，最近一次发生的入场/离场标记"，而不是"恰好在这一 bar 发生的标记"。要找到标记首次出现的精确 bar，需要观察相邻行的变化。

## 3. 50 列数据详解

parquet 文件的 50 列 = 2 个固定列 + 4 个视图 x 12 个视图列。

### 固定列（2 列）

| 列名 | 来源 | 说明 |
|------|------|------|
| `bar_index` | runner 循环变量 | min_tf 全局 bar 索引（300~799） |
| `bar_timestamp` | DB kline.ts | 该 bar 的 UTC 时间戳（datetime64[ns]） |

### 每视图 12 列（v{0,1,2,3}_*）

| 列名 | 来源 | 取值方式 | 说明 |
|------|------|---------|------|
| `sig` | `schmitt["sig"][-1]` | 取最后一个 | +1做多, -1做空, 0中性, NaN=无数据 |
| `filtered` | `filtered[-1]` | 取最后一个 | 滤波后的价格 |
| `eps` | `schmitt["eps"][-1]` | 取最后一个 | 噪声强度估计 |
| `pnl_long` | `long_pnl[-1]` | 取最后一个 | 做多累计净值（起点=100） |
| `pnl_short` | `short_pnl[-1]` | 取最后一个 | 做空累计净值（起点=100） |
| `long_pos` | `long_mask[-1]` | 取最后一个 | 是否持有多头仓位（bool） |
| `short_pos` | `short_mask[-1]` | 取最后一个 | 是否持有空头仓位（bool） |
| `trade` | `trade_records`遍历 | `<= view_last_idx` | 最近交易事件，如 "entry_long", "exit_short" |
| `trade_return` | `trade_records`遍历 | 同上匹配 | 该笔交易收益率%（仅exit时有值） |
| `trade_reason` | `trade_records`遍历 | 同上匹配 | 离场原因：eod/stop_loss/take_profit |
| `bs_entry` | `entry_markers`遍历 | `<= view_last_idx` | 最近入场标记，如 "B"(买), "S"(卖) |
| `bs_exit` | `exit_markers`遍历 | `<= view_last_idx` | 最近离场标记，如 "B", "S" |

**注意：** `long_pos` 和 `short_pos` 来自 `long_mask`/`short_mask`，这是跨周期对齐后计算的持仓掩码，与信号 `sig` 不完全等价。掩码考虑了高周期持仓约束。

## 4. 与 Streamlit 回测的差异分析

### 4.1 Streamlit 看到的 vs Parquet 存储的

**Streamlit 实时回测中：**
- 每个 bar 步进时，显示完整管道输出 `stage_output`
- 图表上画出完整的 120 点滤波曲线、信号变化、PnL 曲线
- 用户看到的是一个**动态演进的完整时间序列**，每个曲线有 n_pts 个点

**Parquet 存储：**
- 每行只存每个数组的 `[-1]`（最后一个值）
- 500 行 x 50 列
- 用户看到的是一个**逐 bar 快照的表格**

### 4.2 PnL 曲线：n_pts 个点 vs 1 个终值

假设 v0（15分钟）窗口有 50 个点，Streamlit 在每个 bar 步进时画出一条 50 点的 PnL 曲线。Parquet 只存这条曲线的最后一点。

**为什么这不是 bug：**

在 bar_index=350 时：
- `long_pnl` 数组 = `[100.0, 100.12, 99.87, ..., 106.97]`（50 个值）
- `long_pnl[-1]` = 106.97 → 存入 parquet 的 `v0_pnl_long` 列

在 bar_index=351 时：
- `long_pnl` 数组 = `[100.0, 100.12, ..., 106.97, 106.92]`（50 个值，窗口向右滑动 1 格）
- `long_pnl[-1]` = 106.92 → 存入 parquet 的 `v0_pnl_long` 列

**parquet 中 `v0_pnl_long` 列的 500 个值串起来，就是 PnL 终值的逐 bar 演化轨迹。** 它不等同于 Streamlit 中任何单条曲线的全部点，而是每条曲线的最后一个点按时间串联。

### 4.3 信号变化：完整序列 vs 逐 bar 快照

同样是"完整曲线 vs 最后一个点"的关系：

- Streamlit 绘制的 `schmitt["sig"]` 曲线有 n_pts 个点，显示信号如何在窗口内变化
- Parquet 的 `v0_sig` 列有 500 个值，每个值是当时窗口内最后一个信号状态

**重要：** parquet 中 `v0_sig` 的相邻行可能在长时间内保持同一值（如连续 10 行都是 1），这反映的是 15 分钟级别信号在连续 bar 上未变化。但窗口内部的信号历史（如 5 个 bar 前信号从 -1 翻转到 +1）无法从 parquet 单行数据直接还原。

### 4.4 为什么"看起来不一样"但是数据正确的

| 维度 | Streamlit 图表 | Parquet 表格 |
|------|---------------|-------------|
| 时间精度 | 实时，每个 bar 重绘全窗口 | 逐 bar 快照，事后分析 |
| 数据维度 | 每步是 n_pts 长度的数组 | 每步是 1 个标量值 |
| PnL 曲线 | 一条完整曲线（n_pts 点） | 500 个终值串起来的演化线 |
| 信号翻转 | 可在窗口内任意位置翻转 | 只知道每个 bar 的当前信号 |
| 用途 | 可视化验证策略逻辑 | 统计分析、策略评估、报告生成 |

**总结：两者描述的是同一件事的不同切面。** 将 parquet 的 `v0_pnl_long` 列按 bar_index 画出折线图，就能得到 PnL 随时间变化的曲线——这和 Streamlit 中动态显示的 PnL 尾值演化是等效的。

### 6.3 找出信号翻转的精确 bar

由于 BS marker 存储的是累积状态（`<=` 匹配），要找出标记**首次出现**的 bar：

```python
# 找出 v2（日线）BS entry 标记首次出现 "B" 的 bar
bs_entry = df['v2_bs_entry'].fillna('')
flip_points = df[bs_entry != bs_entry.shift(1)]
first_b = flip_points[bs_entry == 'B']
print(f"v2 日线 B 入场上一次出现: bar {first_b['bar_index'].iloc[-1]}")
```

### 6.4 还原窗口内完整曲线的局限性

**无法从 parquet 直接还原：**
- 窗口内部 PnL 的完整 50/60 点轨迹（只有终值）
- 信号在窗口内翻转的精确位置（只知道当前信号方向）
- 预测曲线的形状参数（`prediction_pairs` 未落地为列）

**可以还原：**
- 每个 bar 的当前状态快照（信号方向、持仓、PnL 终值、滤波价格）
- 状态的时间演化（信号翻转时机、PnL 增长轨迹）
- 交易事件的时序（配合 `trade`, `trade_reason` 列）
- BS 标记的累积历史（通过对比相邻行）
