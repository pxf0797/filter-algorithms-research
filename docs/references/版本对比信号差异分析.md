## 2. 信号识别差异明细

### P0: 首个信号段交易生成

| 维度 | 76ee7f0 (旧) | HEAD (新) |
|------|-------------|----------|
| **变更位置** | `filter_engine.py` `_compute_strategy_pnl` | 同位置 |
| **入场时机** | `entry_idx = pair_end` | `entry_idx = pair_start` |
| **信号判定** | `v2 = sig_t[pair_end]` | `v2 = sig_t[pair_start]` |

**问题**: 旧代码在信号段结束时才入场(`pair_end`是下一段的开始), 导致:
- 第一个信号段的持仓方向被跳过
- 若整个窗口只有一个信号段(全+1或全-1), 完全不会产生交易
- PnL 曲线在这种情况下始终为 100(无交易基准)

**修复**: 入场改为 `pair_start`(信号段起始点), 第一个信号段也能正确产生交易对。

**输出差异**:
| 列 | 76ee7f0 | HEAD |
|----|---------|------|
| `_pnl_long` | 首个信号段为 100(无交易) | 首个信号段有真实 PnL 值 |
| `_pnl_short` | 首个信号段为 100 | 首个信号段有真实 PnL 值 |
| `_long_pos` | 首个信号段为 False | 首个信号段可为 True |
| 交易对数量 | N-1 对(N个信号段) | N 对(每个信号段都有) |

**示例**: AAPL, 15分钟视图, 窗口前 50 个 bar 全部 sig=+1
- 76ee7f0: PnL = 100,100,100,... (无交易)
- HEAD: PnL = 100,100.2,99.8,101.1,... (真实盈亏)

### P1: PnL 空 pred_pairs 回退

| 维度 | 76ee7f0 (旧) | HEAD (新) |
|------|-------------|----------|
| **变更位置** | `backtest_core.py` `run()` | 同位置 + `_compute_strategy_for_view` |
| **空 pred_pairs** | PnL 返回全 100 数组 | 前向传播上一个有效 PnL 值 |

**问题**: 当 `show_pred=False` 或抛物线拟合失败时, `pred_pairs` 为空列表, 旧代码直接返回全 100 的 PnL 数组, 而信号图正常显示 ±1, 产生直接的「信号有方向但 PnL 死平」矛盾。

**修复**: 在 `run()` 中追踪 `_prev_pnl_state`(per-view), 当 pred_pairs 为空时传入 `prev_long_pnl`/`prev_short_pnl`, `_compute_strategy_for_view` 检测到空 pairs 且信号活跃时, 将上次 PnL 值填入当前 bar 的输出数组。

**输出差异**: 空 pred_pairs 期间 PnL 列不再全部=100, 而是保持最近有效值。

---

### P4: 持仓状态数据源

| 维度 | 76ee7f0 (旧) | HEAD (新) |
|------|-------------|----------|
| **变更位置** | `parquet_store.py` + `event_recorder.py` `_extract_view_columns` | 同位置 |
| **`_long_pos` 来源** | `long_mask` (跨周期对齐) | `trade_records` (本周期) |
| **`_short_pos` 来源** | `short_mask` (跨周期对齐) | `trade_records` (本周期) |

**问题**: 旧代码从高层周期的 `long_mask`/`short_mask` 派生低层周期的持仓状态。由于跨周期对齐逻辑与 PnL 计算逻辑不同, 可能出现「PnL 在赚钱但持仓热力图显示空仓」（或反之）的矛盾。

**修复**: 改从 `view_data[trade_records]` 遍历, 按 `entry_idx`/`exit_idx` 判定当前 bar 是否处于活跃交易中, 方向由 `trade[type]` 决定。这样 `_long_pos`/`_short_pos` 与 `_pnl_long`/`_pnl_short` 来自同一计算源, 天然一致。

**输出差异**:
| 列 | 76ee7f0 | HEAD |
|----|---------|------|
| `_long_pos` | 可能与本周期 PnL 方向矛盾 | 与本周期 PnL 一致 |
| `_short_pos` | 同上 | 同上 |
| `_trade` | 旧逻辑 | 基于 trade_records |
| `_trade_reason` | 旧逻辑 | 基于 trade_records |
| `_trade_return` | 旧逻辑 | 基于 trade_records |

### P5: BS 标记事件语义

| 维度 | 76ee7f0 (旧) | HEAD (新) |
|------|-------------|----------|
| **变更位置** | `parquet_store.py` + `event_recorder.py` line ~527 | 同位置 |
| **匹配方式** | `if int(m[0]) <= view_last_idx` | `if int(m[0]) == view_last_idx` |
| **行为** | 标记一旦产生, 永久存在于后续所有 bar | 只在事件发生的精确 bar 上出现 |

**问题**: `<=` 语义使得 B/S 标记像持久状态(类似 `_long_pos`), 而不是交易事件。用户看信号对比图表时, 会看到大片连续的 B 标记, 无法判断实际交易发生的时刻。

**修复**: 改为 `==` 精确匹配, B/S 标记仅在交易执行的那一个 bar 上出现。信号对比图表中标记变为离散的点/短线段。

**输出差异**: `bs_entry`/`bs_exit` 列 — 旧版大部分 bar 有值, 新版只有事件 bar 有值。

### P3: 时间维度说明

 | 维度 | 说明 |
|------|------|
| **变更位置** | `tests/test_backtest.py` `TestTimeDimension` |
| **性质** | 文档性修复, 非代码逻辑变更 |

三种时间维度:
1. **信号(sig)**: 瞬时 — bar 结束时即刻反映 Schmitt 状态
2. **PnL**: 累计 — 从交易开始到当前 bar 的累积结果
3. **持仓(pos)**: 滞后 — 信号变化后需要开仓/平仓逻辑, 持仓状态变化晚于信号

P3 通过测试代码和注释明确了这三种维度之间的关系, 帮助理解「信号变了但 PnL/持仓还没变」属于正常行为。

## 3. 问题解决说明

| 根因 | 原始问题 | 修复方案 | 验证方法 |
|------|---------|---------|---------|
| P0 | 首个信号段不产生交易对 | entry_idx 改为 pair_start | `_find_all_pairs` 测试: 单段/两段/三段 |
| P1 | 空 pred_pairs 时 PnL 死平 100 | 前向传播 prev PnL | PnL fallback 测试: 连续空 pairs |
| P2 | 信号图与持仓图分离 | 前端叠加持仓状态带 | HTML overlay 测试: rgba 颜色存在 |
| P3 | 时间维度混淆 | 文档+测试明确三种维度 | TestTimeDimension 测试 |
| P4 | PnL 方向与持仓矛盾 | 持仓从 trade_records 计算 | 同 bar PnL 与 pos 一致性测试 |
| P5 | BS 标记永久残留 | <= → == 事件语义 | 标记只在事件 bar 出现测试 |

**整体效果**: 1082 测试通过, 0 失败。信号、PnL、持仓三种数据在输出中保持一致, BS 标记从持久状态变为离散事件。

## 5. 结论

`76ee7f0` → `HEAD` 的核心变化是**信号到 PnL 全链路的正确性修复**:

- **之前**: 首个信号段被跳过, PnL 空仓时死平, 持仓方向可能矛盾, BS 标记永久残留
- **现在**: 每个信号段都产生交易, PnL 空仓时前向传播, 持仓与 PnL 方向一致, BS 标记精准显示交易时刻

两个版本用相同配置跑同一 ticker 的回测数据, 主要差异体现在: PnL 列不再有虚假的 100 值, 持仓列与 PnL 方向一致, BS 标记变为离散事件而非连续带。
