## 3. 核心模块速查

### backtest_core.py (862 行，新增)

- **职责**：零 Streamlit 依赖的回测引擎，逐 bar 迭代运行 6 步管线
- **核心类/函数**：`BacktestRunner`、`replay_bar()`
- **关键方法**：`run(start, end, interval)` → 返回 per-step output 列表；`_compute_pipeline_for_view()` → 6 步管线（filters → schmitt → pairs → prediction → strategy PnL → masks/BS）
- **连接**：被 CLI/工具调用 → 驱动 EventRecorder → 复用 filter_engine、data_loader、bs_marker
- **值得注意**：
  - 跨窗口 EWMA 状态缓存（`_ewma_state`），消除滑动窗口边界处的信号跳变
  - TF 粗→细排序（周线 → 日线 → 60分钟 → 15分钟），保证跨周期 PnL 对齐
  - `replay_bar()` 自动 clamp bar_index 到 `max(n_pts)`，保证窗口数据充足

### event_recorder.py (825 行，新增)

- **职责**：Event Sourcing 风格的事件记录器，每步追加 5 个 JSONL 流 + CSV
- **核心类/函数**：`EventRecorder`、`CSVBuilder`
- **关键方法**：`record_step()` → 逐视图写 filter_tail/schmitt_snapshot/trade_summary/BS events/BS snapshot；`CSVBuilder.accumulate()` → 构建 47 列行
- **连接**：被 CLI 调用 ← 从 BacktestRunner 输出消费 → 产出给下游分析工具
- **值得注意**：
  - PnL 冻结逻辑：持仓平仓后锁定 PnL 值，防止滑动窗口漂移
  - Trade 匹配策略经过 3 轮修复：Exit 仅在 `== view_last_idx` 且非 EOD；Entry 在 `<= view_last_idx` 且无 exit 或 EOD exit
  - BS 标记身份使用 `(bar_idx, label, date)` 三元组
  - CSV ffill 处理：`-` → NaN → ffill → 恢复 `-`

### parquet_store.py (715 行，新增)

- **职责**：Append-only 列式存储，50 列 PyArrow schema，分段写入 + 最终合并
- **核心类/函数**：`ParquetStore`
- **关键方法**：`append_row()` → 提取并缓冲一行；`flush()` → 原子写入 part 文件（ZSTD L3）；`end_session()` → 合并 part 为 backtest_result.parquet + 导出 CSV
- **连接**：被 CLI 调用（`--save-data` 开关） ← 从 BacktestRunner 输出消费 → 被 view_backtest / replay_bar 读取
- **值得注意**：
  - 原子写入：`.tmp` + `os.replace()` 保证崩溃安全
  - 分段策略：每 100 行或 30 秒 flush 一次
  - `start_session()` 清理残留 `.tmp` 文件
  - PnL 冻结逻辑与 CSVBuilder 完全一致（双轨实现，保持 parity）

### pipeline_capture.py (299 行，新增)

- **职责**：Feature-flag 门控（`PIPELINE_CAPTURE=1`）的管线数据捕获，用于回测调试
- **核心类/函数**：`PipelineCapture`、`PipelineStageData`（`__slots__` 优化内存）
- **关键方法**：`capture_step(step_index, cutoff_date, views_data)` → 逐视图写 parquet/JSON
- **连接**：被 Streamlit 调用 ← 从 `_render_chart()` 捕获 → 被 analyze_captured_backtest 消费
- **值得注意**：
  - 默认关闭（环境变量门控），零侵入
  - 跳过 stages 01(raw)、02(markers)、06(prediction)、08(higher_pnl) —— 可派生或已在缓存中
  - 使用 `__slots__` 减少内存占用（每步 4 视图 × 1 对象）

### backtest_cli.py (541 行，新增)

- **职责**：CLI 入口，串联 BacktestRunner + EventRecorder + ParquetStore(可选)
- **核心函数**：`main()` → 验证 ticker → 加载配置 → 确定 bar 范围 → 运行回测 → 保存数据 → 打印摘要
- **关键参数**：`--ticker`(必填)、`--preset`/`--config-file`(互斥)、`--save-data`(Parquet)、`--view-filter`(单视图调试)
- **连接**：创建 Runner/Recorder/Store 三个实例，共享同一输出流
- **值得注意**：
  - 配置灵活：支持 preset(DB)、JSON 文件、默认配置三种方式
  - KeyboardInterrupt 被捕获，触发优雅的 `end_session()`

### view_backtest.py (331 行，新增)

- **职责**：读取 Parquet → 序列化为 column-major JSON → 嵌入 HTML 模板 → 打开浏览器
- **核心函数**：`embed_and_open()` 四步流程；`start_server()` HTTP 拖放上传模式
- **连接**：读取 ParquetStore 输出 → 嵌入 `docs/backtesting/回测结果可视化.html`
- **值得注意**：
  - column-major 序列化：转置行式 parquet 为列数组，便于 JS 渲染
  - 自实现 multipart 解析（RFC 1867），零外部依赖
  - 自动发现同目录 metadata.json

### replay_bar.py (246 行，新增)

- **职责**：重建单个 bar 的完整管线状态（重新计算，非回放存储数据）
- **核心函数**：`main()` → 支持 `--parquet`（从 metadata 读配置）或 `--ticker --preset`
- **连接**：调用 `backtest_core.replay_bar()` → 输出可读摘要或完整 JSON
- **值得注意**：
  - "Replay" = 重新计算，不是数据回放 —— 保证与 Streamlit 实时计算完全一致
  - bar_index 边界自动 clamp

### analyze_captured_backtest.py (539 行，新增)

- **职责**：分析 PipelineCapture 会话数据，逐步骤 diff、BS 稳定性追踪、级联放大检测
- **核心类**：`StepDiff` dataclass（含 `is_stable`、`has_structural_jump` 判断）
- **输出**：步骤级 diff 报告、BS 标记持久性分析、Schmitt pair 数时间线、级联放大指标
- **连接**：读取 PipelineCapture session → 输出 TEXT/JSON 报告到 `analysis/` 子目录
- **值得注意**：
  - `_compact_ranges()`：压缩索引列表为 `[4-6,10,12]` 格式，提升可读性
  - 级联放大量化：`eps_amplification` = schmitt_eps_max_diff / filter_max_diff

## 5. 数据流详解

一次完整的 CLI 回测运行数据流：

```
1. 触发
   $ python -m filter_app.backtest_cli --ticker AAPL --preset AAPL_US --save-data
   → backtest_cli.main() 解析参数，加载配置

2. 初始化
   → BacktestRunner(ticker, configs)     — 确定 min_tf, 查询总 bar 数, 初始化 EWMA 缓存
   → EventRecorder(output_dir, ticker)   — 创建 session 目录, 打开 5 个 JSONL 句柄
   → ParquetStore(output_dir, ticker)    — 构建 50 列 PyArrow schema, 写初始 metadata

3. 逐 bar 迭代 (runner.run(start, end))
   对每个 bar_index:
   a. _sync_data(cutoff_date)           — 同步所有 TF display parquet (复用 data_loader)
   b. _load_window_data(tf, n_pts)      — 从 data/display/{ticker}/{tf}.parquet 加载
   c. 逐视图计算 6 步管线 (TF 粗→细):
      filters → schmitt(EWMA 状态连续性) → prediction_pairs → strategy PnL → masks(higher-TF PnL 对齐) → BS markers
   d. 收集 stage_output dict → 返回给 CLI 主循环

4. 每步记录
   EventRecorder.record_step():
   → 逐视图写 filter_tail / schmitt_snapshot / trade_summary / BS events / BS snapshot
   → CSVBuilder.accumulate() — 构建 47 列行 (7 OHLCV + 10×4 视图)
   ParquetStore.append_row():
   → _extract_row() — 构建 50 列行 (2 固定 + 12×4 视图)
   → 缓冲满 100 行或 30 秒 → 原子写入 part_NNNN.parquet (ZSTD L3)

5. 结束
   EventRecorder.end_session():
   → 关闭所有 JSONL 句柄, 更新 metadata, CSVBuilder.write() 输出 CSV
   ParquetStore.end_session():
   → flush 剩余缓冲, _merge_parts_and_export_csv() 合并 part 文件
   → 写入 backtest_result.parquet + backtest_result.csv
   → 更新 metadata (status="completed"), 删除 part 文件

6. 消费
   view_backtest.py:
   → load_parquet() → df_to_columns() (column-major)
   → embed_and_open() — 注入 HTML → 浏览器展示交互图表
   replay_bar.py:
   → 从 metadata.json 读取配置 → 调用 replay_bar() 重建单 bar 状态
   analyze_captured_backtest.py (如使用 PipelineCapture):
   → 逐步骤 diff → BS 持久性 → 级联放大 → 输出分析报告
```

**设计原则贯穿全流程：**

- **零侵入**：所有 record/append 异常被捕获，记录日志，不中断回测
- **原子写入**：`.tmp` + `os.replace()` 保证文件完整性
- **三级持久化**：ParquetStore(类型化列式) / EventRecorder JSONL(可观测) / PipelineCapture(调试)
- **Ticker 隔离**：所有路径含 ticker code，并行安全

## 7. HTML 可视化特性

`docs/backtesting/回测结果可视化.html` 是一个自包含的单文件交互式仪表盘（无外部依赖，仅 CDN 加载 Plotly.js），支持嵌入模式（Python 脚本注入 JSON）和拖放模式（浏览器直接加载 Parquet）。

### 7.1 概览仪表盘（Section 1）

- **KPI 卡片**：最佳做多/做空 PnL、总交易次数、信号覆盖率
- **参数摘要表**：每个周期的 eps 均值、信号翻转次数、PnL 终值、交易/BS 计数

### 7.2 Filtered 价格总览（Section 2）

- 4 条滤波价格线叠加（v0-v3），使用分层线宽（短周期=细，长周期=粗）
- v2（日线）eps 阈值半透明带
- **收盘价参考线**：薄灰色半透明线（`rgba(200,200,200,0.3)`，线宽 1），作为所有滤波价格线的背景参考
- 横轴使用 bar_index（等间距），避免周末/隔夜空白被 Plotly 连成直线
- 每 ~50 bar 显示一个日期标签

### 7.3 信号对比（Section 3）

- 4 视图独立子图，垂直堆叠，共享 x 轴
- 阶梯信号线（`shape: 'hv'`），分层线宽和透明度
- 背景着色：绿色(+1)/红色(-1)/灰色(0) 信号值矩形带
- 持仓叠加带：做多=绿色半透明(`rgba(0,255,0,0.08)`)，做空=红色半透明(`rgba(255,0,0,0.08)`)

### 7.4 PnL 曲线（Section 4-4c）

- 做多（实线）+ 做空（虚线），每条线终值标注
- 基线（PnL=100）参考虚线
- 多 Ticker PnL 叠加图（Section 4b）：每个 ticker 一条曲线，支持 `tk.color` 专属颜色
- 多 Ticker 汇总表（Section 4c）：并排对比各 ticker 终值

### 7.5 持仓热力图（Section 5）

- 100 点采样，行=视图 x (做多+做空)，列=时间

### 7.6 周期仪表盘（Section D1-D4）

每个周期（日线/60分钟/15分钟/5分钟）一个统一子图仪表盘，包含 4 行：

## 8. 潜在问题与改进方向

### 架构层面

- **streamlit_app.py 热点**：该文件从原有功能基础上新增了 capture 生命周期管理（init/capture_step/end_session），行数已超 2,100 行。回测相关的状态管理和生命周期逻辑可以抽取到独立的 service 模块中，减轻主文件的复杂度。
- **EventRecorder 与 ParquetStore 的数据提取逻辑重复**：两者都有 `_extract_view_columns` 逻辑和 PnL 冻结逻辑，但分别实现在不同文件中。如果其中一个修复了 bug，另一个可能遗漏。建议合并到一个共享的 "data extraction" 工具模块。

### 性能考量

- **50 列 schema 的列数膨胀**：当前每增加一个视图（4 视图 = 48 列），列数线性增长。如果未来视图数量增加（例如 8 个时间周期），将达到 98 列。可考虑将 per-view 列按视图分表存储，或使用嵌套结构。
- **JSONL → CSV → Parquet 三阶段管线**：EventRecorder 写 JSONL+CSV，ParquetStore 写 Parquet+CSV。对于生产级回测，这两条路径可能产生重复数据。建议明确各路径的使用场景（Parquet = 生产，JSONL = 调试），并提供只启用其中一条路径的选项。
- **分段 flush 的 100 行阈值**：对于百万级 bar 的回测，100 行的 flush 阈值会产生 10,000 个 part 文件，合并时的 I/O 开销较大。可考虑根据总 bar 数动态调整阈值。

### 代码组织

- **`tools/` 与 `filter_app/` 的边界**：`tools/view_backtest.py` 依赖 `filter_app/services/parquet_store.py` 的输出，但自身放在项目根目录的 `tools/` 下。如果读者不确定代码库结构，可能难以发现这个依赖关系。建议在 `tools/` 的 `__init__.py` 或 README 中说明依赖关系。
- **`filter_app/` 根目录逐渐拥挤**：新增了 `backtest_cli.py`，加上已有的 `streamlit_app.py`、`db.py`，根目录文件数增加。如果后续有更多 CLI 入口，可考虑 `filter_app/cli/` 子包。

### 测试覆盖

- **缺少端到端集成测试**：现有测试覆盖了单元层面（列提取、事件记录、PnL 冻结），但缺少 "从 CLI 启动 → 完整运行 → 验证 Parquet 内容" 的集成测试。建议添加至少一个 e2e 测试，覆盖最小 bar 范围的完整流程。
- **`test_backtest.py` 的行数未计入文件清单**：code-understanding.md 提到该文件有 1,183 行且有修改，但 file-inventory.md 中未列出。建议核实该文件是否确实在本次分支中变更，如果是，补入清单。
- **PipelineCapture 无测试**：`pipeline_capture.py` 作为新的 service 模块没有对应的单元测试文件。虽然它是调试工具，但 `start_session` / `capture_step` / `end_session` 生命周期和文件写入逻辑应至少覆盖基本路径。
