# 研究简报

## 1. 核心问题
如何通过 CLI 方式将回测（backtest）的所有数据按最小周期步长持久化存储，替代当前 Streamlit 仅内存展示的模式。

## 2. 拆解维度
- **维度 A — 现状分析**：当前回测系统（streamlit_app.py）的架构、数据流、结果结构、周期粒度
- **维度 B — 数据结构**：回测结果包含哪些字段（OHLCV、信号、仓位、权益曲线等），步长粒度的含义
- **维度 C — 存储方案**：CLI 入口设计、输出格式选型（CSV/Parquet/JSON/HDF5/SQLite）、文件组织方式
- **维度 D — CLI 设计**：命令行参数设计、与现有 Streamlit 参数的对应关系、批量运行支持

## 3. 范围边界
- ✅ 研究如何从 CLI 运行回测并存储数据
- ✅ 确定合适的存储格式和文件组织
- ✅ 给出完整的方案设计文档
- ❌ 不实现代码（用户明确要求"不着急实现代码"）
- ❌ 不修改 Streamlit UI
- ❌ 不改动回测核心逻辑

## 4. 不确定项
- 待 Agent 分析 streamlit_app.py 后确认：回测引擎的具体实现、最小周期的实际含义
- 待 Agent 探索项目结构后确认：是否已有 CLI 入口、数据存储相关代码
