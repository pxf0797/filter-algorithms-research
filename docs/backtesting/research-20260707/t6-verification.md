## A.1 逻辑一致性

### Level 0-4 依赖关系

| 依赖关系 | 判定 | 说明 |
|---------|------|------|
| L0 (Bug修复) → L1 (信号稳定) | 正确 | Bug修复是后续工作的基础，脏数据上做信号稳定无意义 |
| L1 → L2 (多周期协同) | 正确 | 多周期Gating依赖稳定的单周期Sig，否则门控决策本身也在闪烁 |
| L2 → L3 (风险管理) | 正确 | 动态止损和仓位管理需要可信的信号方向和多周期对齐分数 |
| L3 → L4 (验证框架) | 正确 | 参数敏感性分析需要策略行为已稳定，否则heatmap反映的是噪声而非参数效果 |

**结论**: 依赖关系正确，不存在循环依赖或跳跃依赖。

### 低级方案是否会被高级方案推翻

| 潜在冲突 | 判定 | 分析 |
|---------|------|------|
| L1.2(锁定Sig) vs L2.1(高周期门控) | 无冲突 | L2.1是后处理步骤，在L1.2锁定的Sig输出之上运行。高周期门控读取的是已锁定的高周期Sig，决策稳定。 |
| L1.2(锁定Sig) vs L1.3(信号确认) | 需明确顺序 | L1.3在`_schmitt_trigger`内部增加确认逻辑，L1.2在输出端锁定。正确顺序：确认(内部) → 锁定(外部)。边缘区内信号不稳定，确认计数器可能反复重置，这正是期望行为——不稳定区不产生确认信号。**T5未明确此顺序，建议补充。** |
| L1.2边缘区(N=filter_window/2) vs L2.1高周期数据可用性 | 潜在问题 | L2.1提到"what if higher-TF data is not yet available for the most recent bars?"。如果高周期最新bar也在边缘区内（Sig=pending），门控无法执行。T5已识别此风险但未给出具体处理方案。 |

**结论**: 无致命矛盾。L1.3与L1.2的交互顺序需在实现时明确，L2.1的边缘情况需补充处理逻辑。

|------|-----|---------|------|
| L1.2 edge_zone = filter_window/2 | SMA下~10 bar | L1.3 confirm_bars=2 | 无矛盾，确认窗口(2)远小于边缘区(10)，确认信号完全在边缘区内完成 |

### 修改范围合理性

MVP范围: L0.1(5行) + L0.2(15行) + L1.1(30行) + L1.2(80行) = ~130行，4个文件。

- 无过度设计：每个改动直接对应一个问题
- 无不必要的抽象：L1.2直接在`_schmitt_trigger`中扩展而非新建模块
- 改动集中在核心路径上，未触及数据加载、缓存等无关模块

### 遗漏的关键实现细节

1. **L1.2 锁定信号的存储机制** (中等问题): T5说"Store a `_locked_sig` array"，但未指定存储位置。若存于`session_state`，需处理参数变更时的失效逻辑(滤波类型切换、窗口大小改变均应清空锁定)。若每次从数据窗口重新推导"哪些bar已出边缘区"，则需稳定的bar标识机制。**建议**: 在实现时优先考虑基于bar index计算而非session_state存储，避免缓存一致性问题。

2. **L1.2 锁定Sig是否用于下游计算** (重要问题): T5仅提到修改`_schmitt_trigger`和`charts.py`。若锁定的Sig仅用于图表渲染，而`_find_all_pairs`和`_compute_strategy_pnl`仍使用未锁定的原始Sig，则PnL曲线依然不稳定。用户将看到稳定的Sig图表和变化的PnL曲线——这本身就矛盾。**建议**: 明确锁定后的Sig应替代原始Sig流入整个下游链路。

3. **L0.2 cutoff_date关联机制**: "clear or tag all `_pnl_*` session_state keys with a `cutoff_date`"——session_state的值是Python对象(PnL数组)，如何"tag"一个numpy数组？需要改为存储`{"data": ..., "cutoff_date": ...}`结构，或直接在每个frame清除。**建议**: 采用最简单的方案——每个frame清除所有`_pnl_*`键并重新计算。

## A.3 大方向正确性

### 是否真正解决了"动态变化导致误操作"的核心问题

T4识别的核心因果链:

```
新1 bar数据 → 滤波边界效应 → EWMA sigma_v传播 → Schmitt状态机级联 → PnL重建
```

T5方案的对应关系:

| 因果链环节 | 对应方案 | 解决方式 | 有效性 |
|-----------|---------|---------|--------|
| 滤波边界效应(最上游) | L1.1: 因果滤波默认 + 非因果滤波警告 | 消除根因 | **高**。SMA仅最后1-2 bar受影响，vs Butterworth全局变化 |
| EWMA sigma_v传播(放大器1) | L1.2: 边缘锁定(间接缓解) | 限制影响可见范围 | **中**。EWMA仍在传播，但配合L1.1后传播范围已缩小到2-5 bar |
| Schmitt状态机级联(放大器2) | L1.2: 历史锁定 | 阻断级联的可见传播 | **高**。历史bar锁定后级联无法改写已确认信号 |
| PnL重建(最终表现) | L0.1+L1.2 | Bug修复+锁定Sig稳定输入 | **中高**。前提是锁定Sig流入PnL计算 |

**核心逻辑判断**: T5的策略是在两个层面同时入手——(1) 源头削减(L1.1减少滤波边界效应) 和 (2) 末端隔离(L1.2防止变化传播到用户可见的历史)。这是一个正确的双层防御策略。

### L0+L1能否从根本上改善信号稳定性

**定量预期** (基于T4的影响量化数据):

| 指标 | 当前(Butterworth) | 仅L1.1(SMA) | L1.1+L1.2(SMA+锁定) |
|------|-------------------|-------------|---------------------|
| 历史Sig变化概率 | ~95% | ~5-10% | 0% (历史已锁定) |
| 变化的bar数 | 全部120 bar | 最后1-2 bar | 仅边缘区(pending标记) |
| PnL曲线变化幅度 | 面目全非 | 仅最后1-2笔微调 | 仅边缘区交易可能变化 |
| 用户看到的信号闪烁 | 频繁且无声 | 偶尔(仅右端) | 不存在(闪烁被pending明确标注) |

**结论**: L0+L1的组合从根源和表现两个层面大幅改善了稳定性。95%→0%的历史信号变化概率是质变。

### 是否有更简单但同样有效的替代方案被遗漏

| T4建议的替代方案 | T5是否采纳 | 评估 |
|-----------------|-----------|------|
| EWMA→滚动窗口标准差(B1) | 未采纳 | 合理省略。配合L1.1(因果滤波)后，EWMA的全局传播范围已从60+ bar缩小到2-5 bar，替换收益有限，且滚动窗口引入新参数(窗口大小)和相位滞后 |
| 统一前向差分替代np.gradient(B2) | 未采纳 | 合理省略。边界差分退化影响范围仅1-2 bar，通过L1.2的边缘区标记已充分覆盖 |
| Butterworth lfilter替代filtfilt(B3) | 部分采纳 | L1.1提及作为可选方案，非默认。合理——lfilter有相位滞后trade-off，留给高级用户选择 |
| pair合并逻辑修改(B4) | 未采纳 | 合理省略。合并逻辑本身是局部纯函数，不稳定来自输入Sig，修复Sig后无需修改合并逻辑 |

**替代方案遗漏评估**: 无关键遗漏。T5选择的方案组合在简洁性和有效性之间取得了良好平衡。L1.1(改默认值+警告)是最简单且收益最大的单一改动；L1.2(边缘锁定)是解决残余不稳定性的最小化方案。
